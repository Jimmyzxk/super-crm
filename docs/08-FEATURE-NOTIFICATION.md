# 功能规格：通知提醒

版本：v1.0 · 2026-08-11
场景依据：[02-USERS-AND-SCENARIOS.md](./02-USERS-AND-SCENARIOS.md)

---

## 1. 这个模块做什么

销售闭环的第 5 步：**到点提醒我**。

销售答应客户"周三回电"，到了周三却在处理其他事务。**没有提醒，这条线索就会停滞、无人跟进。**

---

## 2. 为什么通知在核心而不是插件

按 [产品概览](./01-PRODUCT-OVERVIEW.md) 5.1 判定：卸载通知 → 超时无人知晓 → 闭环第 5 步断 → **核心**。

> **这一环最容易被跳过。**
> 它有完整的通知模块：4 种渠道、投递账本、重试机制、管理员投递日志页面。
> 但销售侧**完全没有入口**——API 只有 `GET /notifications/deliveries`（管理员看投递记录）和 `POST /deliveries/:id/retry`。
> 前端唯一的通知页面挂在 `/admin/notifications`，权限是 `notification.read`。
> 销售看不到，没有铃铛，没有未读数。**管道全建好了，但水从来没流到销售那里。**

---

## 3. V1 只做站内通知

**不做**：短信、邮件、企微、App 推送。

那些是插件（见 [13 插件契约](./13-PLUGIN-CONTRACT.md)）。理由：各家用的服务商不同，且都需要外部账号和费用，不是 V1 闭环必需。

**站内通知足够闭环成立**：销售每天开着 CRM，铃铛红点能被看到。

---

## 4. 通知类型

核心链路触发以下类型（`notification_type` 枚举中另有若干来自业务插件的类型，开源版不会产生）：

| 类型 | 触发条件 | 标题模板 | 跳转 |
|---|---|---|---|
| `TASK_OVERDUE` | 任务已超时 | `{对象名}的{任务类型}已超时` | 线索/商机详情 |
| `TASK_DUE_SOON` | 任务临近到期 | `{对象名}的{任务类型}即将到期` | 同上 |
| `LEAD_ASSIGNED` | 线索分配给我 | `新线索已分配给你：{姓名}` | 线索详情 |
| `RECYCLE_WARNING` | 线索/客户临近回收阈值 | 回收预警提示 | 对应详情 |
| `RECYCLE_EXECUTED` | 公海回收已执行 | 回收通知 | 线索池 |
| `MORNING_COPILOT` | 晨会副驾驶生成今日建议 | 今日工作建议 | 工作台 |
| `CHAMPION_PRACTICE` | 销冠打法发布 | 新打法可用 | 打法库 |

新增类型需同步更新 `notification_type` 枚举与扫描去重逻辑（`(task_id, type)` 唯一约束）。

### 4.1 标题示例

```
李明的首次响应已超时
星海智能科技的跟进任务即将到期
Q3 设备采购的阶段推进已超时
新线索已分配给你：王芳
```

### 4.2 正文

正文补充关键信息，一句话：

```
已超时 3 天，截止时间 08-08 10:00
还剩 1 小时 20 分钟
来自官网表单，评分 72
```

## 5. 触发机制

### 5.1 超时与临近到期：定时扫描

```
每 5 分钟执行一次：

① 查 tasks：status = OPEN 且 due_at < now
   → 对每条，若未通知过，生成 TASK_OVERDUE

② 查 tasks：status = OPEN 且 now <= due_at <= now + 2h
   → 对每条，若未通知过，生成 TASK_DUE_SOON
```

**去重是关键**：同一任务的同一类型通知**只发一次**。

实现：`notifications` 表加唯一约束 `(task_id, type)`。重复插入静默忽略。

> **为什么不重复提醒**：连续提醒同一件事会让销售关掉通知。宁可提醒一次被忽略，不可提醒五次被屏蔽。

### 5.2 线索分配：即时触发

分配动作完成后立即生成通知，同一事务内。

### 5.3 定时任务实现

**V1 不引入队列系统**（BullMQ / Redis 队列）。

方案：Next.js Route Handler `POST /api/cron/scan-tasks` + 外部定时调用（系统 cron 或平台定时器）。

- 需要密钥校验（`CRON_SECRET`），防止被外部随意调用
- 单次执行上限 1000 条，超过下次继续
- 执行时间超过 30 秒记警告

> **为什么不用 BullMQ**：一个定时任务不需要队列系统。引入它意味着 Redis + worker 进程 + 监控 + 失败重试，是典型的"为想象中的规模建基础设施"——业界实践最贵的错误。

## 6. 收件箱

### 6.1 入口：铃铛 + 未读数

导航栏右上角铃铛图标。有未读时显示红点和数字（>99 显示 `99+`）。

**这个入口必须在每个页面都可见。**

### 6.2 收件箱页面

```
┌────────────────────────────────────────┐
│ 通知                      [全部标记已读] │
├────────────────────────────────────────┤
│ ● 李明的首次响应已超时                  │
│   已超时 3 天，截止 08-08 10:00         │
│   2 分钟前                              │
├────────────────────────────────────────┤
│ ● 王芳的跟进任务即将到期                │
│   还剩 1 小时 20 分钟                   │
│   1 小时前                              │
├────────────────────────────────────────┤
│   新线索已分配给你：张伟                │
│   来自官网表单，评分 65                 │
│   昨天                                  │
└────────────────────────────────────────┘
```

- `●` = 未读标记
- 未读的背景色略深
- 按创建时间倒序

### 6.3 交互

| 动作 | 结果 |
|---|---|
| 点击通知 | 标记已读 → 跳转到对应线索/商机 |
| 点「全部标记已读」 | 当前用户所有未读置为已读 |
| 下拉/点击加载更多 | 每次 20 条 |

### 6.4 已读状态

`read_at` 为 null 表示未读。点击时写入当前时间。

**不做**：已读后再标记为未读。无使用场景。

## 7. 数据保留

| 规则 | 说明 |
|---|---|
| 保留期 | 90 天 |
| 清理 | 定时任务顺带清理超过 90 天的通知 |
| 已读的通知 | 同样保留 90 天，不提前删 |

---

## 8. 边界情况

| 情况 | 处理 |
|---|---|
| 任务超时后被完成，通知已生成 | 通知保留（它是历史记录），点击后跳转正常 |
| 线索被删除，通知还在 | 点击跳转显示"该线索已不存在"，通知可手动删除 |
| 负责人变更后，旧负责人的通知 | 保留（他确实收到过），新负责人不补发 |
| 定时任务连续失败 | 记错误日志；V1 不做告警（无告警基建） |
| 定时任务重叠执行 | 用数据库行锁防重入（`SELECT ... FOR UPDATE SKIP LOCKED`） |
| 用户被停用 | 不再生成新通知，已有通知保留 |
| 同一任务先发了 DUE_SOON 后又超时 | 两条都发（不同 type，唯一约束不冲突） |
| 时区 | 存 UTC，前端按浏览器时区显示 |

### 8.1 外部群机器人 Webhook 派发扩展（可选通道）

为支持高优先级事件向企微/钉钉/飞书群机器人通知，系统支持通过配置租户级 Webhook URL 异步派发：

1. **触发事件**：
   - `TASK_OVERDUE`（任务严重超时）；
   - `LEAD_ASSIGNED`（高评分优质线索进线并分配）；
2. **Payload 标准结构**：
   ```json
   {
     "event": "NOTIFICATION_TRIGGERED",
     "tenantId": "...",
     "type": "TASK_OVERDUE",
     "title": "李明的首次响应已超时",
     "body": "...",
     "link": "...",
     "occurredAt": "2026-08-18T10:00:00Z"
   }
   ```
3. **安全与隔离**：
   - 异步非阻塞派发，Webhook 目标服务响应慢或失败不得阻塞核心业务事务与站内通知生成；
   - 默认超时 3 秒，失败记录审计日志，不进行无限重试。

## 9. 明确不做

| 不做 | 理由 |
|---|---|
| 短信 / 邮件 / 企微 / App 推送 | 插件，各家服务商不同 |
| 通知偏好设置（哪些要收） | V1 只有三种，没有配置必要 |
| 免打扰时段 | 站内通知不打扰，无需求 |
| 通知聚合（"你有 5 条超时"） | 单条更可点击、可跳转 |
| 主管收下属的超时通知 | 主管通过列表筛选查看，不需要被动打扰 |
| @提及 / 站内信 / 评论 | V1 不做协作功能 |
| 通知已读同步到多设备 | 已读状态存服务端，天然同步 |

- [ ] 同一任务同一类型只通知一次（不重复轰炸）
- [ ] 点击通知 → 标记已读 → 正确跳转
- [ ] 「全部标记已读」生效
- [ ] 线索分配后，新负责人立即收到通知

- [ ] 定时任务重叠执行不会重复生成通知
