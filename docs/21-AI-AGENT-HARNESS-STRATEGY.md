# AI Agent Harness 战略章程（docs/21）

> 版本 v1.0 · 2026-08-31 · 本文是所有 AI 能力迭代的总章程与排序依据
> 一句话：**马具是约束与工具，目标驱动驾驭，最终形成真实价值闭环的 AI。**

## 一、为什么要有这份章程

历史教训（见复盘记录）：本项目的 AI 曾长期处于"prompt 函数"状态——喂答案的质检、模板拼接的自学习、硬编码的假指标。根因不是模型不行，而是**没给模型上马具**：没有工具、没有循环、没有目标函数，AI 就只是"一张嘴"。

本章程定义：马具（载体）→ 客户经营认知（导航）→ 自治阶梯（进化）三层结构，任何 AI 功能立项必须说清自己在三层中的位置。

## 二、三层结构

```
┌─────────────────────────────────────────────────┐
│  第三层：自治阶梯（进化机制）                       │
│  采纳率是货币；逐级解锁自主权；学习飞轮反哺          │
├─────────────────────────────────────────────────┤
│  第二层：客户经营认知（导航系统）★终极目标           │
│  AI = 客户资产的解释器 + 经营决策的指挥官            │
│  为什么是销冠 → 客户画像 → 如何获客/转化/增量/变现   │
├─────────────────────────────────────────────────┤
│  第一层：马具 Harness（载体与约束）                 │
│  工具层（service 注册为可调用工具）                  │
│  循环层（推理→调工具→观察→再推理，上限 8 轮）        │
│  护栏层（RLS 租户隔离 / 审计 / Token 预算 / 确认闸门）│
└─────────────────────────────────────────────────┘
```

**铁律：三层缺一不立项。** 只有马具没有目标是炫技；只有目标没有马具是 PPT（历史上的假 AI 均属此类）；没有进化机制则永远停在演示。

## 三、第二层详解：客户经营认知金字塔（AI 的终极目标）

AI 的终极任务不是记录（CRM 已做），而是**解释 + 指挥**：

| 层 | 回答的问题 | 数据基础 | 现状 |
|---|---|---|---|
| L1 赢单归因 | 为什么赢/输/停滞/续约 | opportunities + 输单归因 + 跟进 | 有事实统计，缺因果解释 |
| L2 销冠解构 | 销冠的客户是什么样子？路径差在哪？ | 赢单数据按 owner 对比 | 零 |
| L3 企业画像 | 客户盘子结构：钱从哪来、谁在流失 | customers + 回款 + 生命周期 | 有总量，缺结构诊断 |
| L4 策略推导 | 获什么客、怎么转化、找谁增量变现 | L1~L3 综合 | 零（"指导+分析"的最终产出） |

**认知先行原则**：AI 说不清"我们为什么赢单"，就没资格指挥获客。L4 的合法性来自 L1~L3 的证据。

**诚实边界**：真实赢单样本 < 20 时，所有结论标注为"方向性假设（低置信度）"，人的经验权重高于数据。数据增厚，AI 逐步接棒。

## 四、第一层详解：马具（复用现有资产）

| 组件 | 设计 | 复用的现有资产 |
|---|---|---|
| 护栏层 | 部分就绪（规划中：Token 预算熔断 90%预警/100%降级尚未实现；已实现：轮数上限 8 + usage 计量） | RLS/TenantContext、audit_logs、轮数上限+usage 计量已实现、Token 预算熔断（90%预警/100%降级）规划中、权限位体系 |
| 工具层 | 读工具先行（查商机/联系人/跟进/管线），动作工具带确认闸门 | 27 个 core 模块 service 层直接包装 |
| 循环层 | ReAct 微循环 + 外层控制流（初始化/终止守卫/错误处理），轮上限 8 | ai-gateway 六厂商网关（支持 function calling） |
| 记忆层 | learning_logs 从死数据变为注入 prompt 的经验 | ai_agent_learning_logs 表 + 学习飞轮（见下） |

## 五、第三层详解：自治阶梯与学习飞轮

### 自治阶梯（自驱力的正确打开方式）

```
L0 观察   AI 只看只报（晨报、巡检）           ← 起步线
L1 建议   AI 给方案，人点确认（一键建任务等）    ← 采纳率 ≥30% 解锁
L2 代办   例行动作 AI 直接做（改期/提醒/待办），审计留痕可撤销
L3 自治   边界内自主行动（停滞打标、战情室预警触发）
```

**解锁条件不是拍脑袋，是上一级的真实采纳率数据。** 采纳率是整个进化体系的货币。

### 学习飞轮（马具里最关键的进化装置）

```
销售采纳/忽略/推翻建议 → 回流为经验记录（learning_logs）
  → 周期提炼"哪类建议被采纳/被无视" → 注入下周巡检与建议策略
  → 建议越来越像本团队销冠，而非通用大模型
```

终态：每个租户的马具骑着同一匹 LLM，却被自己的数据驯出独有骑术——抄不走的护城河。

### 三维赋能（马具的三种骑法，同一套底座）

| 维度 | 受众/频率 | 形态 | 指标 |
|---|---|---|---|
| 销售赋能 | 一线/每日 | 晨会副驾驶：今日三件事+证据+一键动作 | 打开率、周采纳率 |
| 管理赋能 | 主管/每周 | 团队风险巡检官：带证据链的点名报告 | 介入及时率 |
| 企业赋能 | 老板/每月 | 经营诊断：渠道归因、打法有效性、续约预测 | 决策被引用次数 |

## 六、落地路线（与既有计划的对齐）

```
第一坡：马具底座 + 认知先行（约 1.5 周）
  ├─ P1 读工具集（service 包装为工具，马具的手）
  ├─ 销冠解构 v1（L2）：赢单客户结构对比 → AI 第一份"解释器"报告
  └─ 企业画像 v1（L3）：客户盘子结构诊断
第二坡：解释→指挥之桥
  ├─ 转化卡点分析（阶段流失+原因聚类）
  └─ 晨会副驾驶上线：建议依据从规则换成销冠解构结论
第三坡：增量与变现
  ├─ 客户群 ROI 分层 → 增量投入方向
  └─ 变现机会发现：交叉销售/沉睡唤醒/续约窗口
全程：自治阶梯按采纳率解锁；学习飞轮从 v1 起回流数据
```

排序原则：**认知先行，指挥在后**——晨会副驾驶是认知的消费者而非生产者，故排在解构之后。

## 七、护栏红线（沿用既有一票否决）

1. 工具调用全部走 TenantContext，RLS 硬隔离，无任何旁路
2. 写操作动作必须过人工确认闸门或审计留痕（L2 级以下）
3. 公网输入（表单 note 等）在进入 prompt 前必须清洗隔离（既有 `<customer_data>` 机制扩展到全部工具循环）
4. Token 预算熔断复用现有配额体系（现状：轮数上限 8 + usage 计量已实现，90%预警/100%降级熔断规划中、尚未实现）
5. 所有 AI 产出必须可溯源到工具证据（引用工具名+查询参数），禁止无证据结论
6. 诚实标注：置信度、数据边界、规则兜底状态，禁止任何夸大宣称（历史教训）

## 八、自我检验问题（每次 AI 迭代立项前自问）

1. 这个功能在三层结构中的位置是什么？缺哪层？
2. 它消费了哪层认知、产出 feeds 哪层认知？
3. 它的采纳率如何度量？在自治阶梯的哪一级？
4. 冷启动阶段（<20 单）它如何诚实降级？
5. 拿掉这个功能，价值闭环断在哪里？（答不出=不做）
