版本：v1.0 · 2026-08-11
从属于：[00-SCOPE-CONTRACT.md](./00-SCOPE-CONTRACT.md) · 场景依据：[02-USERS-AND-SCENARIOS.md](./02-USERS-AND-SCENARIOS.md)

## 1. 这个模块做什么

客户（Customer）是**已确认有价值的公司**。它由线索升级而来，是商机的载体。

本模块负责：**线索转客户、客户档案、联系人管理、客户时间线**。

`/customers` 是统一客户池。客户池保存客户当前事实；销售视图、主管视图和管理员视图只是不同的查询范围，不各自保存客户副本。

## 2. 核心概念

### 2.1 客户 vs 线索

| | 线索 Lead | 客户 Customer |
|---|---|---|
| 单位 | 一个人 | 一家公司 |
| 可能重复 | 是 | 否 |
| 可能无效 | 是 | 否 |
| 谁创建 | 系统或销售 | **只能销售确认后创建** |
| 有商机吗 | 没有 | 转化时必建首个，之后可以有多个 |

### 2.2 一家公司多个联系人

客户下面挂 Contact（联系人）。一家公司可能有采购、技术、老板三个联系人。

**主联系人**：一家客户有且仅有一个 `is_primary = true` 的联系人。

### 2.3 V1 不做的复杂关系

| 不做 | 理由 |
|---|---|
| 集团/子公司层级 | V1 客户是扁平的 |
| 客户合并 | 转客户时查重已能防大部分重复 |
| 联系人跨客户任职历史 | 过度设计 |
| 客户共享/协作团队 | 一个客户一个负责人够用 |

## 3. 线索转客户

### 3.1 触发

销售在线索详情页或工作台点「转客户并创建商机」。

**前置条件**：线索 `status = QUALIFIED` 且 `owner_user_id` 非空。

- `NEW` / `CONTACTED` 不允许转：没有明确记录需求，不足以进入经营链路
- 未分配线索不允许转：客户和商机都必须有明确负责人，主管需先分配
- 转化不是单独“建客户”，而是一次完成 **Lead → Customer → Opportunity** 的组合动作

### 3.2 查重

按线索的 `contact_phone` 在**当前租户的 contacts 表**中查找。

| 结果 | 处理 |
|---|---|
| 无匹配 | 直接进入创建表单 |
| 有匹配 | 提示「该手机号已关联客户「星海智能科技」」，不允许以相同手机号新建联系人 |

**有匹配时的两个有效选择**：

1. **关联到已有客户** → 不创建 customer/contact；使用命中的联系人作为商机主联系人，并继续创建本次转化商机。该客户已有的其他商机不受影响
2. **修改手机号后创建** → 返回表单，改为未占用手机号后再创建新客户和主联系人

> **绝不自动合并。** 自动合并错了，销售会失去信任，而信任一旦丢失就回不来了。
>
> `contacts.phone` 在租户内唯一，因此不提供“仍以相同手机号创建新客户”按钮。那条路径必然违反数据库约束，不是有效的产品选择。

**已有客户权限**：SALES 只能关联自己负责的客户；命中其他销售负责的客户时提示「该联系人由其他销售负责，请联系主管处理」。MANAGER / ADMIN 可关联租户内任一客户。关联时保留客户原负责人，本次转化商机负责人也使用客户原负责人。

### 3.3 创建表单

| 字段 | 必填 | 默认值 | 校验 |
|---|---|---|---|
| 客户名称（公司） | ✅ | 线索的 `company_name` | 1-100 字符 |
| 所属行业 | ❌ | — | ≤ 50 字符 |
| 所在地区 | ❌ | — | ≤ 50 字符 |
| 公司规模 | ❌ | — | 枚举，见下 |
| 主联系人姓名 | ✅ | 线索的 `contact_name` | 1-50 字符 |
| 主联系人手机 | ✅ | 线索的 `contact_phone` | 手机号格式 |
| 主联系人邮箱 | ❌ | 线索的 `contact_email` | 邮箱格式 |
| 主联系人职位 | ❌ | 线索的 `title` | ≤ 50 字符 |
| 本次商机名称 | ✅ | `{客户名称} - {需求摘要}` | 1-100 字符 |
| 预计金额 | ✅ | — | ≥ 0，单位：分 |
| 预计成交时间 | ✅ | — | 不早于今天 |
| 需求说明 | ✅ | 线索确认需求说明 | 1-500 字符 |

**公司规模枚举**：`1-20` / `21-100` / `101-500` / `501-1000` / `1000+`

**表单预填线索信息、商机名称和需求说明**，销售只需确认并补金额、预计成交时间。这是 30 秒原则的延续。本次转化商机固定从 `DISCOVERY` 开始，不让用户跳过销售阶段。

### 3.4 提交后的副作用

原子执行：

```
① 未命中重复时：创建 customer，owner_user_id = 线索负责人
② 未命中重复时：创建主 contact；命中时：锁定并复核关联权限和手机号
③ 线索 status → CONVERTED，并写状态历史；跨池关系由 `lead_conversions` 唯一记录
④ 创建本次转化 opportunity，stage = DISCOVERY，写 `null → DISCOVERY` 阶段历史
⑤ 写不可变 `lead_conversions`，记录 lead / customer / 本次转化 opportunity / 操作人 / 时间
⑥ 创建该商机唯一的 OPEN `STAGE_PUSH` 任务，完成线索上的 OPEN 任务
⑦ 记录客户、联系人、线索、商机相关审计日志
⑧ 提交后跳转到新商机详情页
```

以上写入必须在**同一个数据库事务**中执行。任一校验、唯一约束、权限检查或写入失败，全部回滚；不得留下孤立客户、已转化但无转化关系或商机的线索，或无阶段任务的商机。

并发重复提交时，只允许一个事务成功；后一个返回 `CONFLICT` 并刷新已完成的转化结果，不得再建客户或商机。

### 3.5 客户经营状态（派生，不落库）

客户不增加可手工修改的 `customer_stage`。它的经营状态由名下商机实时聚合：

| 聚合结果 | 客户页显示 |
|---|---|
| 存在非终态商机 | `推进中`，同时显示最接近成交的进行中阶段 |
| 无非终态商机，且至少一笔 `WON` | `已成交` |
| 商机全部为 `LOST` | `暂无进行中商机` |

同一客户的多笔商机各自推进、互不改写；客户经营状态只做摘要，不反向改变任何商机阶段。

## 4. 客户档案

### 4.1 页面结构

```
┌─────────────────────┬──────────────────┐
│ 左侧：客户全貌       │ 右侧：动作区      │
├─────────────────────┼──────────────────┤
│ 星海智能科技         │ 下一步            │
│ 制造业 · 华东 · 200人│ 待首次响应        │
│                     │ 已超时 3 天       │
│ 联系人               │                  │
│  李明 (主) 138****   │ [记跟进]          │
│  张伟     139****    │ [建商机]          │
│  [+ 添加联系人]      │ [改约时间]        │
│                     │                  │
│ 来源线索             │ 商机 (1)          │
│  官网表单 · 08-08    │  Q3 设备采购      │
│  评分 72 · 理由...   │  谈判中 · ¥12万   │
│                     │  [查看]           │
│ 时间线               │                  │
│  08-10 电话跟进      │                  │
│  08-08 提交表单      │                  │
└─────────────────────┴──────────────────┘
```

**右侧是动作区，不是信息区。** 销售在这一屏能完成跟进。

### 4.2 左侧展示内容

| 区块 | 内容 | 加载 |
|---|---|---|
| 基本信息 | 名称、行业、地区、规模、负责人、创建时间 | 首屏同步 |
| 联系人列表 | 姓名、手机、职位、主联系人标记 | 首屏同步 |
| 来源线索 | 来源、创建时间、评分与理由 | 首屏同步 |
| 时间线 | 跟进记录 + 状态变更，倒序 | **异步** |

### 4.3 右侧动作区

| 动作 | 条件 | 结果 |
|---|---|---|
| 记跟进 | 有权限 | 原地展开表单，见 [04](./04-FEATURE-FOLLOWUP.md) |
| 建商机 | 有权限 | 原地展开表单，见 [07](./07-FEATURE-OPPORTUNITY.md) |
| 改约时间 | 有 OPEN 任务 | 选时间，更新 due_at |
| 编辑客户 | 有权限 | 原地展开表单 |

### 4.4 商机列表

显示该客户的所有商机（含已赢单/丢单），按创建时间倒序。

每条显示：名称、当前阶段、预计金额、预计成交时间。点击进入商机详情。

## 5. 联系人管理

### 5.1 添加联系人

| 字段 | 必填 | 校验 |
|---|---|---|
| 姓名 | ✅ | 1-50 字符 |
| 手机号 | ✅ | 手机号格式，**租户内不可与其他联系人重复** |
| 邮箱 | ❌ | 邮箱格式 |
| 职位 | ❌ | ≤ 50 字符 |
| 设为主联系人 | ❌ | 勾选后原主联系人降为普通 |

### 5.2 主联系人规则

- 每个客户有且仅有一个主联系人
- 创建客户时的联系人自动为主
- 设置新主联系人时，原主联系人自动降级（同一事务内完成）
- **主联系人不能删除**，必须先指定新的主联系人

### 5.3 删除联系人

软删除。有关联跟进记录的联系人**仍可删除**，跟进记录保留（显示"已删除的联系人"）。

## 6. 客户列表

### 6.1 默认视图

| 角色 | 看到 |
|---|---|
| SALES | 自己名下的客户 |
| MANAGER | 团队全部 |
| ADMIN | 租户全部 |

销售默认优先显示需要跟进或存在活跃商机的客户；主管增加长期未跟进、活跃商机数量和负责人分布；管理员侧重来源、数据质量和审计。

客户列表只读取客户当前字段、主联系人摘要、最近跟进时间、下一任务时间和活跃商机数量。联系人全集、商机明细和经营时间线进入详情后分页加载。

### 6.2 筛选

| 筛选项 | 说明 |
|---|---|
| 全部 | 默认 |
| 有进行中商机 | 存在非终态商机 |
| 超时未跟进 | 有超时任务 |
| 无进行中商机 | 所有商机均已进入终态 |

### 6.3 搜索

客户名称、联系人姓名、联系人手机号。前缀匹配 + 手机号全匹配。

### 6.4 排序

默认按最近互动时间倒序。可切换为创建时间。

## 7. 客户时间线

### 7.1 包含什么

| 事件 | 显示 |
|---|---|
| 跟进记录 | 方式 · 结果 · 摘要 · 记录人 |
| 线索创建 | 来源 |
| 转为客户 | 谁转的 |
| 商机创建 | 商机名 |
| 商机阶段变更 | 从 X 到 Y |
| 商机赢单/丢单 | 结果 + 原因 |

### 7.2 不包含什么

- 字段编辑记录（太琐碎，在审计日志里查）
- 评分变化（销售不关心轨迹）
- 系统自动任务的创建/完成

### 7.3 加载

异步，每次 20 条，「加载更多」。基础信息不等它。

## 8. 边界情况

| 情况 | 处理 |
|---|---|
| 转客户时手机号已属于另一客户 | 允许关联已有客户，或修改手机号后创建；相同手机号不能强建 |
| SALES 命中其他销售的客户 | 拒绝关联，提示联系主管；MANAGER / ADMIN 可处理 |
| 客户负责人被停用 | 客户保留，主管可重新分配 |
| 同一客户有两条线索都要转 | 第二条转时命中查重，提示关联到已有客户 |
| 删除唯一联系人 | 拒绝，提示"至少保留一个联系人" |
| 客户有未结束商机时删除客户 | 拒绝，提示"请先处理进行中的商机" |
| 联系人手机号改成已存在的号 | 校验拒绝，提示已被占用 |
| 转客户表单提交时线索已被别人转了 | 提交失败，提示并刷新 |

## 9. 明确不做

| 不做 | 理由 |
|---|---|
| 客户合并 | 转客户查重已防住大部分；真出现由人手工处理 |
| 集团/子公司层级 | V1 扁平结构够用 |
| 客户分级（KA/普通） | 无明确使用场景 |
| 客户共享给多个销售 | 一个负责人够用，共享带来责任模糊 |
| 客户画像/标签体系 | 范围契约第 4 节明确不做自定义字段 |
| 联系人关系图谱 | 过度设计 |

## 10. 验收清单

- [ ] 只有 `QUALIFIED` 且已有负责人的线索允许转客户
- [ ] 转客户时手机号查重生效，命中时只能关联已有客户或修改手机号
- [ ] **绝不自动合并**：命中时必须由人选择
- [ ] SALES 不能关联其他销售负责的客户
- [ ] 转客户表单预填线索信息、商机名和需求说明
- [ ] 转客户后线索变 `CONVERTED`、本次 `DISCOVERY` 转化商机与阶段历史创建、任务正确切换
- [ ] `lead_conversions` 是唯一跨池来源关系；同租户但商机不属于目标客户时数据库拒绝提交
- [ ] 客户、联系人、线索、商机、历史、任务和审计在一个事务中，失败全部回滚
- [ ] 并发重复转化只有一个成功，不产生重复客户或商机
- [ ] 客户经营状态由商机聚合，不存在独立可编辑的客户阶段
- [ ] 客户档案右侧动作区能直接记跟进，不跳转
- [ ] 时间线异步加载，不阻塞首屏
- [ ] 主联系人唯一性：设置新主联系人时原主自动降级
- [ ] 不能删除唯一联系人
- [ ] 不能删除有进行中商机的客户
- [ ] 联系人手机号租户内唯一校验生效
- [ ] 390px 下左右两栏正确堆叠，动作区可访问
