# 页面与交互规格

版本：v1.0 · 2026-08-11

---

## 0. 体验原则（2026-08-14 修订）

界面服务于高频销售动作，不做“每个对象一张大卡”的展示型后台。

1. 每页只有一个主工作区和一个主动作；次要动作进入更多菜单。
2. 桌面列表使用紧凑表格或主从布局，首屏至少看到 8 条业务对象（有数据时）。
3. 详情页顶部直接回答：当前阶段、健康度、下一步、为什么；不得把四者拆散到页面不同位置。
4. 状态历史、跟进、任务和建议合并为一条经营时间线，可按类型筛选。
5. AI 建议显示在业务上下文，不单独堆成“AI 卡片墙”。
6. 所有图标使用统一图标库；图标按钮有 tooltip 和可访问名称。
7. 桌面 1440px 和移动 390px 均无横向滚动；触控目标至少 44px。
8. 空白必须表达结构或状态，不能因单条数据留下大面积失衡页面。
9. 字体、间距、边框、颜色使用全局 token；卡片圆角不超过 8px，不嵌套卡片。
10. 保存后原地反馈且保持滚动和筛选状态，错误紧邻相关字段并给出恢复路径。

### 0.1 信息架构：池是事实，视图是入口

界面只有两类顶层概念：

- **业务池**：线索池、客户池、商机池，负责检索、筛选和操作同一批业务事实；
- **角色视图**：销售工作台、主管经营视图、管理员控制台，负责从三个池中挑出当前角色最需要处理的内容。

角色视图不是新的数据模块。点击任何指标或异常项都必须回到带筛选条件的业务池，不能进入一套平行的“管理后台数据”。

## 1. 五条设计铁律

业界实践的界面被用户评价为「像操作手册」。根因是**页面在描述工作，而不是让人干活**，与视觉美观无关。

以下五条是硬性约束，每个页面完成时逐条自检。**括号里是业界实践真实发生的反例。**

### 铁律 1：一条数据只出现一次

（反例：同一批 5 条线索在一屏里出现 4 次——优先队列、时效提醒、开放待办、底部表格，页面高 4092px，真实信息量 5 条）

**做法**：分组用**筛选标签切换**，不是并列多个列表。

### 铁律 2：动作是按钮，不是文字

（反例：`<span>现在做 完成首次响应</span>` —— 把该做什么印出来，让用户自己去别处找地方执行）

**做法**：列表项上必须有可点击的业务动作按钮。"下一步：X"如果只是文字，说明设计错了。

### 铁律 3：零值不占位

（反例：首屏三个指标「已超时 5 / 临近到期 0 / 建议评估商机 0」，两个 0 占据黄金位置）

**做法**：指标为 0 时**不渲染**。全为 0 时显示空状态而不是一排 0。

### 铁律 4：不解释界面

（反例：「本页用于……」「请先选择……」「按待办时效、评分和渠道状态排序」）

**做法**：界面呈现事实，不讲解自己。用户需要读说明才会用，说明设计不够直观。

### 铁律 5：一屏干完

（反例：读到"下一步：完成首次响应"，却要跳到另一个页面才能执行）

**做法**：主要动作在当前页面原地展开完成，不跳转。

### 1.1 每条数据的展示标准

列表里的每一项，必须同时回答销售的三个问题：

```
是谁？        →  姓名 + 公司
为什么是他？  →  评分 + 一句人话理由 + 距离超时多久
我现在做什么？→  可点击的按钮（不是文字）
```

**三者缺一，这一项就是"信息"而不是"工作"。**

## 2. 四态规范

每个数据区块必须处理四种状态。**缺任何一种都算未完成。**

| 状态 | 表现 | 禁止 |
|---|---|---|
| 加载中 | 骨架屏（保持布局稳定） | 禁止显示"读取中"文字占位 |
| 空 | 一句话说明 + 一个下一步动作按钮 | 禁止空表格、禁止显示 0 |
| 出错 | 一句话说明原因 + 重试按钮 | 禁止只显示"加载失败" |
| 无权限 | 不渲染该区块 | 禁止渲染后禁用 |

### 2.1 骨架屏 vs 加载文字

业界实践的 `WorkItemCard` 写的是 `{{ lastInteraction ?? '读取中' }}`，导致未加载的卡片**永久显示"读取中"**——那不是加载中，是根本不会加载。

**规则**：加载态必须由明确的 `isLoading` 标志驱动，不能用"数据为空"推断。

## 4. 页面规格

### 4.1 今日工作台 `/today`

**一句话**：从三个业务池中提取当前角色最需要处理的内容。

#### 布局

```
┌────────────────────────────────────────┐
│ 今天要跟 8 条            第 1 / 8 条    │
├────────────────────────────────────────┤
│                                        │
│  已超时 3 天              待首次响应    │
│                                        │
│  李明                                  │
│  星海智能科技                          │
│  138****1001          ← tel: 可拨号    │
│                                        │
│  72 分                                 │
│  填了公司名 +20，来自表单 +15          │
│                                        │
│  来源 官网表单                         │
│  最近互动 还没有跟进记录               │
│                                        │
│  [记跟进] [转客户并建商机] [改约] [跟不了]│
│                                        │
├────────────────────────────────────────┤
│      [上一条]   第 1/8   [下一条]       │
└────────────────────────────────────────┘
```

#### 数据来源

SALES 读取当前用户名下 `status = OPEN` 的任务及其关联对象，排序见 [04](./04-FEATURE-FOLLOWUP.md) 5.3。MANAGER 读取团队池的未分配、超时、停滞和负载异常聚合；ADMIN 读取配置、来源、数据质量和审计异常。三者都不建立工作台专用业务表。

#### 交互

| 动作 | 行为 |
|---|---|
| 记跟进 | **原地展开**表单 → 提交 → 本条标记已处理 → **自动跳下一条** |
| 转客户并建商机 | 仅 `QUALIFIED` 且已有负责人时显示；提交组合表单 → 成功进入商机详情 |
| 查看客户 | 仅 `CONVERTED` 时显示；进入关联客户档案，不在工作台另建商机 |
| 改约 | 原地展开时间选择 → 提交 → 自动跳下一条 |
| 跟不了 | 原地展开原因表单 → 提交 → 自动跳下一条 |
| 手机号 | `tel:` 链接直接拨号（脱敏号码不可拨） |
| 上一条/下一条 | 手动切换，不标记已处理 |

#### 四态

| 状态 | 表现 |
|---|---|
| 加载中 | 卡片骨架屏 |
| 全部处理完 | 「今天的 8 条都处理完了」+ [去看全部线索] |
| 本来就没有 | 「今天没有待处理的线索」+ [去看全部线索] |
| 出错 | 「工作台加载失败」+ [重试] |

#### 已处理逻辑

前端维护本次会话的 `handledIds`，已处理的不再出现。**不重新拉取队列**——重拉会让顺序变化，销售会困惑"刚才那条去哪了"。

#### 4.1.1 极速智能跟进与 AI 洞察一键采纳交互

1. **30 秒极速跟进交互**：
   - 销售点击「记跟进」后，可在快捷输入框中直接粘贴或键入简述（如“电话沟通意向强，客户提到预算充足，下周二做方案展示”）；
   - 点击「智能提炼」按钮，前端即时调用跟进解析器，自动选中 `CALL`、`INTERESTED`，高亮提取异议/需求标签，并将建议下次跟进时间自动填充为“下周二”；
   - 销售可一键点击「提交跟进并完成待办」，30 秒内一气呵成。
2. **AI 洞察卡片交互**：
   - 每条洞察卡片提供明确的证据展开、建议动作以及两个按钮：
     - **[一键采纳]**：直接依据洞察的 `suggestedAction` 与 `suggestedDueAt` 创建对应下一步任务，洞察状态变为 `ACCEPTED`；
     - **[忽略]**：展开快速原因选择器（`不适用` / `已在其他渠道处理` / `客户信息有误` / `其他`），提交后洞察状态变为 `DISMISSED`。

### 4.2 线索池 `/leads`

**一句话**：同一个线索池，按角色确定默认范围和可用动作。

**与工作台的分工**：工作台 = 今天该干的活（任务驱动）；线索页 = 我名下所有线索（对象驱动）。**动作完全一致，共用同一个卡片组件。**

#### 布局

```
┌────────────────────────────────────────┐
│ 线索池                      [+ 新建]    │
│                             [导入]      │
├────────────────────────────────────────┤
│ [全部 42] [超时 3] [高分 8] [疑似重复 2]│
│ 🔍 搜索姓名 / 手机号 / 公司              │
├────────────────────────────────────────┤
│ ┌────────────────────────────────────┐ │
│ │ 已超时 3 天         待首次响应      │ │
│ │ 李明  星海智能科技                  │ │
│ │ 72 分 · 填了公司名 +20，来自表单+15 │ │
│ │ 来源 官网表单 · 还没有跟进记录       │ │
│ │ [记跟进][转客户并建商机][改约][跟不了]│ │
│ └────────────────────────────────────┘ │
│ ┌────────────────────────────────────┐ │
│ │ 还剩 5 小时         待跟进          │ │
│ │ 王芳  云启数据                      │ │
│ │ ...                                │ │
│ └────────────────────────────────────┘ │
│                            [加载更多]   │
└────────────────────────────────────────┘
```

新建表单沿用 [03](./03-FEATURE-LEAD.md) 的负责人规则：SALES 不显示负责人选择，MANAGER 可选 active SALES/MANAGER，ADMIN 必须选择 active SALES/MANAGER；未分配入口（CSV、表单、外部 API）不创建首次响应任务。

#### 关键约束

- **一条线索只渲染一次**（铁律 1）。筛选标签是切换视图，不是并列三个列表。
- 卡片动作随状态变化：`QUALIFIED` 显示「转客户并建商机」；`CONVERTED` 只显示「查看客户」；其他状态不显示转化动作。
- 卡片动作与工作台完全一致。
- 搜索是主要入口，**不折叠、不隐藏**。

#### 筛选标签

只渲染**数量 > 0** 的标签（铁律 3）。「全部」始终显示。
MANAGER/ADMIN 多一个「未分配」。

#### 四态

| 状态 | 表现 |
|---|---|
| 加载中 | 3 个卡片骨架 |
| 空（无线索） | 「还没有线索」+ [新建线索] [导入] |
| 空（筛选后无结果） | 「没有符合条件的线索」+ [清除筛选] |
| 搜索无结果 | 「没有找到匹配的线索」 |
| 出错 | 「线索加载失败」+ [重试] |

### 4.3 客户池 `/customers` 与 `/customers/[id]`

#### 列表页

结构同线索页：筛选标签 + 搜索 + 卡片列表 + 加载更多。

卡片显示：客户名、主联系人、商机数、最近互动、下一步动作按钮。

#### 详情页

```
┌─────────────────────┬──────────────────┐
│ 星海智能科技         │ 下一步            │
│ 制造业 · 华东 · 200人│ 待首次响应        │
│ 负责人 张三          │ 已超时 3 天       │
│                     │                  │
│ 联系人               │ [记跟进]          │
│  李明 (主) 138****   │ [建商机]          │
│  张伟     139****    │ [改约时间]        │
│  [+ 添加联系人]      │                  │
│                     │ 商机 (1)          │
│ 来源线索             │  Q3 设备采购      │
│  官网表单 · 08-08    │  商务谈判 · ¥12万 │
│  72 分 · 理由...     │  [查看]           │
│                     │                  │
│ 时间线    (异步)     │                  │
│  08-10 电话 已接通   │                  │
│  08-08 提交表单      │                  │
│  [加载更多]          │                  │
└─────────────────────┴──────────────────┘
```

**右侧是动作区，不是信息区**（铁律 5）。销售在这一屏能完成跟进。

**时间线异步加载**，基础信息不等它。

客户档案头部显示由商机实时聚合的经营状态（`推进中 / 已成交 / 暂无进行中商机`），不提供独立的客户阶段编辑器。一个客户有多笔商机时，商机区逐笔展示并独立操作。

#### 线索转化表单

`QUALIFIED` 且已有负责人的线索详情显示「转为客户并创建商机」。表单同时承载客户、主联系人和本次转化商机字段：

- 预填客户名、联系人、商机名和已确认的需求说明
- 预计金额、预计成交时间必填；初始阶段固定为 `DISCOVERY`
- 手机号查重命中时，只显示「关联已有客户」和「修改手机号」；不显示“仍然创建”
- SALES 命中其他销售负责的客户时只显示归属提示，不显示关联提交按钮
- 提交期间禁用按钮；`CONFLICT` 时刷新并跳转到已经创建的商机，避免用户重复提交
- 成功后直接进入新商机详情，不停留在客户页要求再建一次商机

### 4.7 表单获客插件

#### 管理页 `/p/form-capture`

- **MANAGER / ADMIN** 可访问；SALES 服务端跳回工作台。
- 左侧按更新时间显示草稿和已发布表单；右侧创建草稿，默认锁定必填的姓名、手机号。
- 只提供 8 类字段：单行文本、手机号、邮箱、公司、单选、多选、下拉、隐私同意。
- 发布是不可逆动作：发布后显示公开链接，不提供原地编辑；插件停用时保留列表，但创建、发布和公开收集全部不可用。
- ADMIN 可在管理页和设置页启停；MANAGER 只能查看状态和管理表单。

#### 公开页 `/f/:formId`

- 无需登录；只渲染已发布、插件启用、租户活跃的表单，其余统一 404。
- 提交中禁用按钮；校验失败保留全部已填内容；成功后只显示收到信息，不暴露 Lead 或租户标识。
- 移动端单列，控件触摸高度至少 44px；多选必填由提交前显式校验，不使用不可聚焦的隐藏控件。

#### 线索详情挂载

表单线索在侧栏显示来源表单、提交时间和按字段标签排列的原始答案。销售仍只可查看自己负责的线索；插件停用或挂载渲染失败时，该区块不出现，核心详情页继续可用。

## 5. 表单规范

### 5.1 校验时机

- **失焦时**校验单个字段
- **提交时**校验全部
- 提交中禁用按钮并显示"提交中"，防重复提交

### 5.2 错误展示

错误信息显示在**字段下方**，红色，一句话。

不用弹窗、不用顶部汇总。

### 5.3 校验文案

见各功能规格文档的字段表。统一原则：

| 好 | 坏 |
|---|---|
| 请填写正确的手机号 | 格式错误 |
| 公司名称不超过 100 字 | 长度超限 |
| 下次跟进时间不能早于现在 | 时间无效 |

### 5.4 提交失败

**保留已填内容**，显示错误原因和重试按钮。绝不清空表单。

## 6. 响应式

### 6.1 断点

| 断点 | 布局 |
|---|---|
| ≥ 1024px | 侧边导航 + 主区（详情页左右两栏） |
| 768-1023px | 侧边导航收窄 + 主区（详情页单栏堆叠） |
| < 768px | 导航收进汉堡菜单 + 单栏 |

### 6.2 390px 硬性要求

**销售在外面用手机，这不是次要场景。**

- 页面级**禁止横向滚动**（宽表格自己内部滚）
- 卡片动作按钮**换行**，不横向滚动，不被挤出屏幕
- 触控目标 ≥ 44×44px
- 表单可正常填完并提交

> 业界实践有一条真实教训：销售说"手机上按钮被挤出屏幕，在外面用不了，就不用了"。

## 7. 视觉规范

### 7.1 色彩语义

| 语义 | 用途 |
|---|---|
| 品牌色 | 主操作按钮、当前导航、链接 |
| 危险（红） | 已超时、丢单、删除类操作 |
| 警告（琥珀） | 临近到期、待处理 |
| 成功（绿） | 已完成、赢单 |
| 中性灰 | 次要信息、辅助文字 |

**状态不能只靠颜色表达**，必须同时有文字（无障碍要求）。

### 7.2 一个页面一个主操作

主按钮实底，次按钮描边，第三级用文本链接。

**一屏出现两个实底主按钮 = 设计错误。**

### 7.3 密度

- 卡片内边距 16-18px
- 卡片间距 12px
- 5 条线索应能在一屏内看到（1080p 桌面）

> 业界实践的教训：单列卡片流在数据多时会显得冗长。密度要控制。

## 8. 页面验收清单

**每个页面完成时逐条回答。任一不通过则不算完成。**

- [ ] 同一条数据在这一页出现了几次？（必须 = 1）
- [ ] 列表项上有可点击的业务动作按钮吗？（必须有）
- [ ] 销售能不离开这一页完成主要任务吗？（必须能）
- [ ] 有多少句在"解释界面"而不是"呈现事实"？（必须 = 0）
- [ ] 指标为 0 时还渲染吗？（必须不渲染）
- [ ] 四态都实现了吗？（加载/空/错误/无权限）
- [ ] 加载态由 `isLoading` 驱动，不是由"数据为空"推断？
- [ ] 评分显示理由了吗？（必须显示）
- [ ] 390px 下有页面级横向滚动吗？（必须没有）
- [ ] 390px 下动作按钮完整可见可点吗？（必须是）
- [ ] 无权限的按钮和导航项是不渲染，还是渲染后禁用？（必须不渲染）
- [ ] 表单提交失败后保留了已填内容吗？（必须保留）
- [ ] 一屏出现了几个实底主按钮？（必须 ≤ 1）
