# 产品定位与价值

版本：v1.0 · 2026-08-11

---

## 1. 我们在解决什么问题

### 1.1 真实场景

一家 20-100 人的 B2B 公司，有 5-20 个销售。线索从官网表单、展会名单、渠道合作、老客户转介绍进来。

**现在的状态通常是这样的**：

- 线索躺在 Excel、微信群、销售个人的手机备忘录里
- 谁跟了谁没跟，只有销售自己知道
- 主管想知道进展，只能开会问
- 上周那条"挺有意向"的线索，这周没人记得跟进
- 换人时，客户关系跟着人走，公司留不下

### 1.2 他们买过 CRM，但没用起来

这才是真正的问题。中小 B2B 公司大多买过 CRM，结果是：

| 现象 | 原因 |
|---|---|
| 销售不填，主管天天催 | 填一条要点五六个下拉框，两分钟起 |
| 打开只为交差 | 打开后看到的是一堆列表和报表，不知道今天该干嘛 |
| 数据越来越脏 | 没人维护，重复线索堆积 |
| 最后回到微信和 Excel | 因为那个更快 |

**CRM 失败的原因几乎不是功能少，而是销售不愿意用。**

### 1.3 我们的判断

> 销售愿意用一个工具，只有一个理由：**它帮我多签单，或者帮我省时间。**

不是"管理需要"，不是"流程规范"，不是"数据沉淀"——那些是老板的理由，不是销售的理由。销售不认这些。

所以我们做的不是"管理销售的系统"，是**"帮销售干活的工具"**。

## 2. 产品定位

### 2.1 一句话

> 一个把优秀销售的推进方法沉淀下来，并在每一笔业务中给出可执行建议的 AI CRM。

### 2.2 定位三要素

| | |
|---|---|
| **给谁** | 20-100 人 B2B 公司的一线销售（首要）、销售主管（次要）、管理员（辅助） |
| **解决什么** | 线索管不过来、不知道先跟谁、推进质量靠个人经验、赢单方法无法复制 |
| **凭什么** | 自动识别风险并建议下一步，从真实赢单中沉淀经主管审核的团队打法 |

### 2.3 不是什么

明确划清，防止定位漂移：

| 不是 | 为什么 |
|---|---|
| 不是营销自动化平台 | 那是获客，我们做的是获客之后的转化 |
| 不是数据中台 | 我们不做数据汇聚和分析基建 |
| 不是自由聊天 AI | AI 必须依附 CRM 事实、证据和人工确认，不替销售做业务决定 |
| 不是全功能 CRM | 不做合同、订单、发票、库存、售后 |
| 不是项目管理工具 | 不做甘特图、工时、协作看板 |

### 2.4 产品结构：三个业务池，三类角色视图

CRM 的事实只存在于三个业务池中：

| 业务池 | 负责什么 | 不能替代什么 |
|---|---|---|
| 线索池 | 尚未确认价值的对象、来源、评分、负责人和跟进状态 | 不能直接当客户档案使用 |
| 客户池 | 已确认的公司、联系人、派生经营状态和经营关系 | 不能把每个商机字段堆进客户表 |
| 商机池 | 一笔具体销售机会的阶段、金额、节奏和结果 | 不能脱离客户单独存在 |

销售、主管、管理员不拥有三套数据，而是从同一业务池读取不同范围：

| 角色 | 首要视图 | 主要问题 |
|---|---|---|
| 销售 | 我的工作台 + 我负责的三个池 | 现在该跟谁、下一步做什么 |
| 主管 | 团队经营视图 + 团队三个池 | 哪些数据没人管、哪里停滞、谁需要帮助 |
| 管理员 | 租户管理视图 | 权限、来源、规则、审计和数据质量 |

角色视图只能改变查询范围、聚合方式和可执行动作，不能复制或改写业务事实。

## 3. 核心价值：三件事

我们只承诺三件事。**每一件都直接对应销售的痛点，而不是管理的诉求。**

### 价值 1：打开就知道今天跟谁

**销售的痛**：手上 50 条线索，每天早上第一个问题是"今天先跟谁"。凭感觉挑，容易挑错，也容易漏。

**我们做的**：
- 每条线索**自动**有分数和理由（不需要销售自己判断）
- 今日工作台按"最容易流失"排序：超时的最前，其次今天到期，其次高分未跟
- 一次只显示一条，处理完自动跳下一条

**衡量**：销售打开工作台到开始第一个动作，**不超过 10 秒**。

### 价值 2：跟完 30 秒记完

**销售的痛**：跟进记录是负担。填一条要选跟进方式、结果、意向等级、下次时间、备注……两分钟起，一天十条就是二十分钟。于是不填，于是数据是脏的。

**我们做的**：
- 记跟进只有三个必填：方式（点选）、结果（点选）、一句话摘要
- 其余全部可选
- 在当前页面原地展开，不跳转
- 提交后自动完成当前任务、生成下一步、更新超时状态

**衡量**：记一条跟进**不超过 30 秒**。

### 价值 3：该动的时候提醒我

**销售的痛**：答应客户"下周三联系"，到了下周三忘了。线索就这么凉了。

**我们做的**：
- 任务超时 → 站内通知 + 铃铛红点
- 快到期（2 小时内）→ 提前提醒
- 线索分配给我 → 立即通知

**衡量**：任务超时后 **5 分钟内**收到通知。

## 4. 为什么这三件事是对的

### 4.1 它们构成一个闭环

```
线索进来 → ①告诉我先跟谁 → 我去跟 → ②记一笔 → ③到点提醒 → 回到①
```

**缺任何一环，闭环就断，销售就会退回微信和 Excel。**

- 缺①：面对 50 条线索不知从何下手 → 凭感觉挑 → 漏掉好线索
- 缺②：跟进不记录 → 下次跟进时想不起上次聊了什么 → 客户体验差
- 缺③：答应的时间忘了 → 线索凉掉

### 4.2 它们是"销售的理由"不是"管理的理由"

| 我们做的 | 销售得到 | 管理顺带得到 |
|---|---|---|
| 自动评分 + 排序 | 少动脑，不漏单 | 知道线索质量分布 |
| 30 秒记跟进 | 少花时间 | 过程可见 |
| 超时提醒 | 不丢单 | SLA 可控 |

**顺序很重要**：先让销售得利，管理价值是副产品。反过来做，销售就会抵触。

## 5. V1 范围

### 5.1 V1 做什么

只做上面那个闭环，以及支撑它的最小集合：

| 模块 | 内容 |
|---|---|
| 线索管理 | 录入（手工/导入/表单/API）、去重、分配、状态流转、检索 |
| 跟进与任务 | 记跟进、下一步任务、超时判定、今日工作台 |
| 智能评分 | 规则配置、自动触发、理由生成、销售反馈 |
| 客户管理 | 线索转客户、客户档案、联系人、时间线 |
| 商机管理 | 商机创建、五阶段推进、赢单丢单 |
| 通知提醒 | 三种通知、站内收件箱、未读数 |
| 设置权限 | 用户管理、三个角色、评分规则配置 |
| AI 销售教练 | 推进质检、下一步建议、赢单复盘、团队打法与反馈 |
| 池化数据架构 | 三个事实池、公共过程记录、转化关系、在线热字段和分析汇总 |

对应七个页面：我的工作台、线索池、客户池、商机池、通知、团队打法、设置。AI 建议进入工作台和对象上下文，不另建卡片墙。

### 5.2 V1 不做什么

完整清单见 [产品概览](./01-PRODUCT-OVERVIEW.md) 第 4 节。核心几条：

- 营销活动、渠道管理、归因分析
- 复杂公海规则、自动划转、抢单
- 业绩管理、提成计算
- 自动化营销、批量触达、AI 外呼
- 销售预测、漏斗分析
- 工作流引擎、自定义字段、自定义对象

**这些不是"以后不做"，是"V1 不做"。** 但固定口径的池数量、状态分布和转化统计属于角色视图的基本需要，不被归类为自由分析。什么条件下可以做，见范围契约第 6 节准入规则。

## 6. 核心与插件

### 6.1 判定规则

> 卸载它，系统还能用吗？
> - 不能用 → **核心**
> - 能用 → **插件**

### 6.2 为什么这么分

目标用户是对外卖 SaaS。不同客户的差异集中在**获客方式**和**外部系统对接**上，而销售日常闭环几乎一致。

因此：
- **闭环相关 = 核心**（每家都一样，且不能少）
- **获客与对接 = 插件**（每家都不同）

### 6.3 具体划分

| 能力 | 归属 | 理由 |
|---|---|---|
| 线索、跟进、客户、商机、任务 | 核心 | 闭环骨架 |
| 评分 | **核心** | 卸载后不知道先跟谁，闭环断 |
| 站内通知 | **核心** | 卸载后超时无人知晓，闭环断 |
| 基础报表 | 核心 | 主管角色的最小需求 |
| 表单获客 | 插件 | 有的客户用自己官网表单 |
| 渠道归因 | 插件 | 只有投放的客户需要 |
| 短信/邮件/企微 | 插件 | 各家服务商不同 |
| AI 销售教练 | **核心** | 卸载后无法质检推进和复制赢单方法，智能闭环断开 |
| 自由聊天助手 | 插件/以后 | 不直接承担业务闭环 |
| 外部 CRM 同步 | 插件 | 每家对接的系统不同 |
| 高级报表 | 插件 | 各家关心的指标不同 |

**V1 只实现一个插件（表单获客）**，目的是验证插件接口够不够用。详见 [13 插件契约](./13-PLUGIN-CONTRACT.md)。

## 7. 成功标准

### 7.1 唯一标准

> **至少 1 名非开发者真实销售，在完整 V1 价值链路可用后连续使用 5 个工作日，第 5 天仍主动使用，并实际完成线索、客户、商机、通知和建议相关动作。**

阶段 3.5 的线索工作台试用只能证明早期执行闭环值得继续开发；内部人员自行试跑只能证明流程可运行。两者都不能替代阶段 6 的完整价值验证。

### 7.2 三个价值的量化验收

| 价值 | 验收方式 |
|---|---|
| 打开就知道今天跟谁 | 打开工作台到开始第一个动作 ≤ 10 秒 |
| 跟完 30 秒记完 | 记一条完整跟进 ≤ 30 秒 |
| 该动的时候提醒我 | 任务超时后 ≤ 5 分钟收到通知 |

### 7.3 不作为成功标准

写在这里防止自我安慰：

- ❌ 功能数量
- ❌ 测试覆盖率
- ❌ 代码行数
- ❌ 架构优雅程度
- ❌ 演示效果好
- ❌ 自己觉得好用

## 8. 非功能要求

### 8.1 性能

| 场景 | 目标 |
|---|---|
| 今日工作台首屏 | P95 < 500ms |
| 三个业务池列表（20 条/页） | P95 < 500ms |
| 记跟进提交 | P95 < 300ms |
| 单租户容量基线 | 100 万客户、500 万线索、5000 万跟进记录需通过压测；未达标前不宣称支持 |
| 深分页 | 只允许游标分页，禁止在线请求使用深层 OFFSET |
| 详情历史 | 首屏不加载全量历史，按对象和时间窗口分页 |

### 8.2 可用性

- 浏览器：Chrome / Edge / Safari 最近两个大版本
- 移动端：**必须在 390px 可用**（销售在外面用手机）
- 无横向滚动（页面级）
- 离线：不支持，但网络异常时要有明确提示和重试

### 8.3 安全

- 多租户数据隔离在数据库层强制（RLS），不依赖应用层自觉
- 密码加盐哈希存储
- 会话过期时间可配，默认 7 天
- 所有写操作记审计日志

### 8.4 数据

- 线索、客户、商机支持导出 CSV（客户资产可带走）
- 删除为软删除，保留 30 天
