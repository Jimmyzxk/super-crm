# 功能规格：跟进与任务

版本：v1.0 · 2026-08-11
场景依据：[02-USERS-AND-SCENARIOS.md](./02-USERS-AND-SCENARIOS.md)

---

## 1. 这个模块做什么

销售闭环的第 3、4 步：**我去跟 → 记一笔**。以及支撑第 5 步的任务与超时判定。

包含三部分：
1. **跟进记录（Activity）** —— 记录发生过什么
2. **任务（Task）** —— 记录下一步该做什么、什么时候做
3. **今日工作台** —— 把任务按优先级排好，一次一条推给销售

---

## 2. 设计红线

这个模块最容易做砸。常见的失败模式：

| 红线 | 反例 |
|---|---|
| **记一条跟进 ≤ 30 秒** | 六个下拉框 + 三个必填 → 销售不填 |
| **原地展开，不跳转** | 点"记跟进"跳到新页面 → 上下文丢失 |
| **提交后自动推进** | 提交完停在原地 → 销售要自己找下一条 |
| **超时必须被感知** | 超时了只在列表里标红，没有主动提醒 → 等于没有 |

## 3. 跟进记录

### 3.1 字段

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| 跟进方式 | ✅ | 单选按钮组 | 一次点击 |
| 跟进结果 | ✅ | 单选按钮组 | 一次点击 |
| 摘要 | ✅ | 单行文本 | ≤ 200 字，一句话 |
| 发生时间 | ❌ | 时间选择 | 默认现在 |
| 下次跟进时间 | ❌ | 时间选择 | 填了就建任务 |

**只有三个必填，且两个是点选。** 这是 30 秒目标的前提。

### 3.2 跟进方式（枚举）

| 值 | 显示 |
|---|---|
| `CALL` | 电话 |
| `MEETING` | 会议 |
| `VISIT` | 拜访 |
| `MESSAGE` | 微信/短信 |
| `NOTE` | 内部记录 |

### 3.3 跟进结果（枚举）

| 值 | 显示 | 语义 |
|---|---|---|
| `CONNECTED` | 已接通 | 正常沟通 |
| `NO_ANSWER` | 未接通 | 没人接、关机 |
| `REFUSED` | 明确拒绝 | 对方说不需要 |
| `INTERESTED` | 有意向 | 表达了兴趣 |

> `NOTE` 方式下，结果字段隐藏（内部记录没有"接通"一说）。

### 3.4 提交后的副作用

**这一串必须原子执行**，任一失败则整体回滚：

```
① 写入 activities 记录
② 若线索 status = NEW → 自动改为 CONTACTED
③ 完成当前进行中的任务（status → DONE，completed_at = now）
④ 若填了"下次跟进时间" → 创建新任务 FOLLOW_UP，due_at = 填写的时间
⑤ 触发重新评分（见 05）
⑥ 记审计日志
```

**第 ② 步是自动的**，销售不需要手动改状态——他记了跟进，就说明联系过了。

### 3.5 交互要求

- 在**当前页面原地展开**（工作台内展开、线索详情页内展开），不跳转
- 提交中按钮禁用并显示"提交中"，不允许重复提交
- 提交成功后：
  - 在工作台 → **自动跳到下一条**
  - 在线索详情页 → 就地刷新时间线，表单收起
- 提交失败 → 保留已填内容，显示错误原因和重试按钮

## 4. 任务

### 4.1 任务是什么

任务 = **一个有截止时间的待办**。它是超时提醒的唯一依据。

**没有任务的线索不会被提醒，也不会出现在今日工作台。**

### 4.2 任务类型

| 类型 | 何时创建 | 默认时限 | 挂在谁身上 |
|---|---|---|---|
| `FIRST_RESPONSE` | **有负责人时**：手工录入即建；导入/表单创建的线索在**分配时**建 | 24 小时 | 线索负责人 |
| `FOLLOW_UP` | 记跟进时填了"下次跟进时间" | 用户指定 | 该对象的负责人 |
| `STAGE_PUSH` | 商机进入新阶段时 | 按阶段配置 | 商机负责人 |

> **未分配的线索不建任务**：`assignee_user_id` 非空，且"超时了通知谁"无解。
> 见 [03](./03-FEATURE-LEAD.md) 3.4 与 [11](./11-DOMAIN-AND-DATA.md) 4.7。

**任务归属对象**：`FOLLOW_UP` 按跟进记录挂在哪个对象就挂哪个——
线索上的跟进挂 `lead_id`，客户上的挂 `customer_id`，商机上的挂 `opportunity_id`。三者恰一非空。

### 4.3 任务状态

| 状态 | 含义 |
|---|---|
| `OPEN` | 待处理 |
| `DONE` | 已完成 |
| `CANCELLED` | 已取消（线索被放弃/商机丢单时） |

**同一对象同时只能有一个 OPEN 任务**（线索、客户、商机各自独立计算）。创建新任务前先完成旧的。

数据库层用三个部分唯一索引兜底，见 [11](./11-DOMAIN-AND-DATA.md) 4.7。

**商机任务的切换规则**：商机的唯一 OPEN 任务代表当前最明确的下一步。

- 进入阶段时创建 `STAGE_PUSH`
- 记商机跟进并填写下次时间：完成当前任务，创建 `FOLLOW_UP`
- 完成商机 `FOLLOW_UP` 且未填写下次时间：恢复 `STAGE_PUSH`，`due_at = stage_entered_at + 当前阶段 SLA`；若该时间已过去，任务立即表现为超时
- 当前任务本来就是 `STAGE_PUSH`，记跟进但既未推进阶段也未填写下次时间：保留该任务，不把一次普通沟通误判为阶段已推进
- 真正推进/回退阶段时：完成当前任务并为新阶段创建新的 `STAGE_PUSH`

这样既满足“一对象一个 OPEN 任务”，也不会因为记了一次普通跟进就永久丢失阶段停滞监控。

### 4.4 超时判定

```
超时  = status == OPEN && due_at < now
临近  = status == OPEN && now <= due_at <= now + 2 小时
```

判定是**实时计算**，不落库标记。理由：落库需要定时刷新，容易与真实时间不一致。

> 通知生成需要扫描（见 [08](./08-FEATURE-NOTIFICATION.md)），但那是"是否已通知过"的记录，不是超时状态本身。

### 4.5 改约

销售可以改任务的 `due_at`。

**改约必须记录原因吗？** 不必。V1 不做——增加摩擦，且价值不明。
但改约动作记审计日志（谁、什么时候、从什么时间改到什么时间）。

## 5. 今日工作台

### 5.1 它解决什么

今日工作台是角色视图，不是第四个业务池，也不保存独立业务数据。

| 角色 | 默认内容 |
|---|---|
| SALES | 我的到期任务、高风险建议和可直接执行的下一动作 |
| MANAGER | 团队未分配、超时、停滞和负责人负载异常，点击后回到对应业务池 |
| ADMIN | 系统配置、来源密钥、数据质量和审计异常，不展示虚假的销售待办 |

工作台上的状态变化必须直接修改对应线索、客户、商机、任务或建议；禁止维护一份工作台专用状态副本。

### 5.2 队列内容

当前用户名下、`status = OPEN` 的任务，关联的线索/商机。

**注意**：工作台的单位是**任务**，不是线索。没有 OPEN 任务的线索不进队列。

### 5.3 排序规则

严格按以下顺序，前一档内部再按次级规则：

```
第 1 档  已超时          → 超时越久越靠前（due_at ASC）
第 2 档  今天到期        → due_at ASC
第 3 档  高分未跟进      → score DESC（score >= 70 且从未跟进）
第 4 档  其余 OPEN 任务  → due_at ASC
```

**为什么超时排最前**：超时的线索最容易流失，挽回价值最高。

### 5.4 一次一条

```
┌────────────────────────────────────────┐
│ 今天要跟 8 条          第 1 / 8 条      │
├────────────────────────────────────────┤
│  已超时 3 天            待首次响应      │
│                                        │
│  李明   星海智能科技                   │
│  138****1001            ← 可点击拨号   │
│                                        │
│  72 分 · 填了公司名 +20，官网表单 +15  │
│                                        │
│  来源 官网表单                         │
│  最近互动 还没有跟进记录               │
│                                        │
│  [记跟进] [建商机] [改约] [跟不了]      │
├────────────────────────────────────────┤
│      [上一条]   第 1/8   [下一条]       │
└────────────────────────────────────────┘
```

**每条必须回答三个问题**（见 [10 页面规格](./10-UI-SPEC.md) 第 1 节）：
- 是谁？→ 姓名 + 公司
- 为什么是他？→ 评分 + 理由 + 超时状态
- 我现在做什么？→ 可点击的按钮

### 5.5 处理完自动推进

已处理的条目**本次会话内不再出现**（前端维护 `handledIds`），处理完自动跳下一条。

**为什么不重新拉取**：重新拉取会导致队列顺序变化，销售会困惑"刚才那条去哪了"。

### 5.6 全部处理完

显示：「今天的 8 条都处理完了」+ 「去看全部线索」按钮。

**不显示空表格、不显示 0。**

### 5.7 空队列

如果本来就没有任务：「今天没有待处理的线索」+ 「去看全部线索」。

## 6. 跟进记录的展示

### 6.1 时间线

在线索详情页和客户档案页显示，倒序（新→旧）。

每条显示：
```
08-10 14:30  电话 · 已接通
             对方在选型，下周要方案
             张三
```

### 6.2 加载策略

**基础信息先渲染，时间线异步加载。** 时间线不阻塞首屏。

加载中显示骨架，**不显示"读取中"占位文字**（见 [10](./10-UI-SPEC.md) 铁律 4）。

### 6.3 分页

每次加载 20 条，「加载更多」。

## 7. 边界情况

| 情况 | 处理 |
|---|---|
| 记跟进时线索已被别人放弃 | 提交失败，提示"该线索已被放弃"，刷新页面 |
| 下次跟进时间填成了过去 | 校验拒绝，提示"下次跟进时间不能早于现在" |
| 同一线索已有 OPEN 任务，又填了下次跟进时间 | 完成旧任务，创建新任务 |
| 商机记跟进但未推进、未设下次时间 | 保留当前 `STAGE_PUSH`；若刚完成的是 `FOLLOW_UP`，按当前阶段进入时间恢复 `STAGE_PUSH` |
| 线索负责人被停用，任务还 OPEN | 任务保留，主管重新分配线索时任务跟着转 |
| 工作台加载时任务已被别人完成 | 该条不显示，队列自动跳过 |
| 网络中断时提交跟进 | 保留表单内容，显示重试按钮 |
| 时区 | 全部用 UTC 存储，前端按浏览器时区显示 |

## 8. 明确不做

| 不做 | 理由 |
|---|---|
| 跟进模板 / 话术库 | V1 不做内容管理 |
| 语音转文字记跟进 | 依赖外部服务，是插件 |
| 跟进时长统计 | 管理需求，不是销售需求 |
| 任务委派给他人 | V1 只有线索负责人一个执行者 |
| 重复任务 / 周期任务 | 场景不明确 |
| 任务优先级手动标记 | 优先级由系统算，人工标记会打乱 |

## 9. 验收清单

- [ ] 记一条完整跟进 ≤ 30 秒（实测计时）
- [ ] 三个必填校验正确，两个是点选
- [ ] 提交后：线索状态 NEW→CONTACTED 自动发生
- [ ] 提交后：当前任务自动完成
- [ ] 填了下次跟进时间 → 自动创建新任务
- [ ] 提交后：评分自动重算
- [ ] 在工作台提交 → 自动跳下一条
- [ ] 在详情页提交 → 原地刷新，不跳转
- [ ] 工作台排序：超时的在最前，超时越久越前
- [ ] 工作台：手机号可点击拨号
- [ ] 工作台：全部处理完显示完成态，不显示空表格
- [ ] 下次跟进时间填过去 → 校验拒绝
- [ ] 390px 下记跟进表单可正常填完，按钮不被挤出屏幕
