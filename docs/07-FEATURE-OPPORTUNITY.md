# 功能规格：商机管理

版本：v1.0 · 2026-08-11
场景依据：[02-USERS-AND-SCENARIOS.md](./02-USERS-AND-SCENARIOS.md)

---

## 1. 这个模块做什么

商机（Opportunity）是**一笔具体的、有金额和预计成交时间的生意**。

本模块负责：**商机创建、阶段推进、赢单丢单、停滞识别**。

`/opportunities` 是统一商机池。商机阶段、金额、负责人和结果只有一个事实来源；销售、主管和管理员看到的是同一商机池的不同角色视图。

---

## 2. 核心概念

### 2.1 一个客户可以有多个商机

同一家公司今年买设备、明年买服务，是两个商机。

**不合并、不关联**——每个商机独立走完自己的阶段。

### 2.2 商机必须挂在客户下

没有客户就没有商机。线索不能直接建商机，必须先转客户。

> **为什么**：商机意味着真实的销售机会，而线索还没确认价值。跳过客户直接建商机，会让商机数据充满噪音。

### 2.3 阶段是固定的

V1 五个阶段，**不可配置**。

> **为什么不做可配置阶段**：这是典型的"看起来必要，实际每家都不同"的能力。做成可配置意味着阶段推进规则、SLA、报表全部要跟着动态化，复杂度爆炸。
> 等真实客户提出且说得出具体差异，再走 [产品概览](./01-PRODUCT-OVERVIEW.md) 第 6 节准入规则。

## 3. 商机创建

### 3.1 入口

有两个受控入口：

1. `QUALIFIED` 线索执行「转为客户并创建商机」时，原子创建本次转化商机
2. 客户档案页的「建商机」按钮，用于同一客户后续独立采购机会

线索不能绕过客户直接持有商机；转化入口仍会先创建或关联 Customer，再在同一事务内创建 Opportunity。

### 3.2 字段

| 字段 | 必填 | 默认值 | 校验 |
|---|---|---|---|
| 商机名称 | ✅ | — | 1-100 字符 |
| 预计金额 | ❌ | — | ≥ 0，**单位：分** |
| 预计成交时间 | ❌ | — | 不早于今天 |
| 初始阶段 | ✅ | `DISCOVERY` | 五阶段之一（不含终态） |
| 主联系人 | ✅ | 客户的主联系人 | 该客户下的联系人 |
| 需求描述 | ❌ | — | ≤ 500 字符 |

**金额用分存储**，避免浮点误差。UI 显示为 `¥120,000.00`。

### 3.3 提交后

```
① 创建 opportunity 记录，owner_user_id = 客户负责人
② 写阶段历史 `null → initialStage`
③ 创建阶段推进任务 STAGE_PUSH，due_at 按阶段时限（见 4.3）
④ 记审计日志
⑤ 跳转到商机详情
```

## 4. 阶段

### 4.1 五个阶段

| 阶段 | 值 | 含义 | 是否终态 |
|---|---|---|---|
| 初步接触 | `DISCOVERY` | 了解需求 | 否 |
| 方案沟通 | `PROPOSAL` | 已给方案 | 否 |
| 商务谈判 | `NEGOTIATION` | 谈价格条款 | 否 |
| 赢单 | `WON` | 成交 | ✅ |
| 丢单 | `LOST` | 失败 | ✅ |

### 4.2 合法转换

```
DISCOVERY ──► PROPOSAL ──► NEGOTIATION ──► WON
    │             │              │
    └─────────────┴──────────────┴─────────► LOST
```

**规则**：
- 只能**向前推进一级**，不能跳级（`DISCOVERY` 不能直接到 `NEGOTIATION`）
- **可以回退**到前一阶段（谈崩了退回方案沟通），需填写回退原因
- 任意非终态 → `LOST`，**必填丢单原因**
- 只有 `NEGOTIATION` → `WON`（不能从早期阶段直接赢单）
- 终态不可再变

> **为什么不能跳级**：跳级说明流程没走完，数据会失真。销售如果真的跳过了某阶段，应该快速点两次而不是跳过记录。

> **为什么只能从谈判赢单**：防止销售为了业绩把早期商机直接标赢单。

### 4.3 阶段时限（SLA）

每个阶段有停留时限，超过视为停滞：

| 阶段 | 时限 |
|---|---|
| `DISCOVERY` | 7 天 |
| `PROPOSAL` | 14 天 |
| `NEGOTIATION` | 14 天 |

进入新阶段时创建 `STAGE_PUSH` 任务，`due_at = 进入时间 + 时限`。

### 4.4 推进阶段的操作

| 字段 | 必填 | 说明 |
|---|---|---|
| 目标阶段 | ✅ | 只能选相邻阶段 |
| 推进说明 | ✅ | ≤ 200 字，"为什么可以推进了" |
| 更新预计金额 | ❌ | 可在推进时顺便更新 |
| 更新预计成交时间 | ❌ | 同上 |

**副作用**：
```
① 更新 stage、stage_entered_at
② 完成当前 STAGE_PUSH 任务
③ 创建新阶段的 STAGE_PUSH 任务
④ 写入阶段变更历史
⑤ 记审计日志
```

## 5. 赢单与丢单

### 5.1 赢单

**前置**：当前阶段必须是 `NEGOTIATION`。

| 字段 | 必填 |
|---|---|
| 实际成交金额 | ✅ |
| 实际成交时间 | ✅（默认今天） |
| 成交说明 | ❌ |

**副作用**：stage → `WON`，取消所有 OPEN 任务，记审计。

### 5.2 丢单

**前置**：任意非终态阶段。

| 字段 | 必填 |
|---|---|
| 丢单原因 | ✅ 枚举 |
| 补充说明 | 选 `OTHER` 时必填 |

**丢单原因枚举**：

| 值 | 显示 |
|---|---|
| `PRICE` | 价格不合适 |
| `COMPETITOR` | 选了竞品 |
| `NO_BUDGET` | 预算取消 |
| `NO_DECISION` | 客户未决策 |
| `TIMING` | 时机不对 |
| `OTHER` | 其他 |

**副作用**：stage → `LOST`，取消所有 OPEN 任务，记审计。

### 5.3 终态不可逆

赢单/丢单后不能改回。

**如果真的搞错了**：新建一个商机。原商机保留作为记录。

> **为什么不允许改**：赢单丢单是业绩依据，允许改会破坏数据可信度。

## 6. 风险识别

### 6.1 三种风险状态（实时计算，不落库）

| 状态 | 判定 |
|---|---|
| 正常 | 有 OPEN 的下一步任务且未超时 |
| 临近超期 | 当前唯一 OPEN 任务 2 小时内到期 |
| 已停滞 | 当前唯一 OPEN 任务已超时 |

下一步任务通常是 `STAGE_PUSH`；销售明确约定下次跟进时临时切换为 `FOLLOW_UP`，完成后按 [04](./04-FEATURE-FOLLOWUP.md) 4.3 恢复阶段推进监控。

### 6.2 停滞的处理

- 商机列表里可筛选「停滞」
- 生成超时通知给负责人（见 [08](./08-FEATURE-NOTIFICATION.md)）
- 主管在商机列表能看到团队所有停滞商机

**V1 不做**：自动降级、自动回收、自动提醒主管介入。

## 7. 商机列表

### 7.1 默认视图

| 角色 | 看到 |
|---|---|
| SALES | 自己名下 |
| MANAGER | 团队全部 |
| ADMIN | 租户全部 |

**默认只显示进行中**（非终态）。已赢单/丢单需切换筛选查看。

销售按风险和下一动作排序；主管增加阶段分布、停滞商机、预计成交窗口和负责人负载；管理员侧重权限和审计，不单独维护经营预测。

商机池列表只能读取当前阶段、金额、负责人、客户摘要、下一任务和当前风险。阶段历史、跟进明细和赢单复盘进入详情后分页加载。

### 7.2 筛选

| 筛选项 | 说明 |
|---|---|
| 进行中 | 默认，非终态 |
| 停滞 | 当前唯一 OPEN 任务超时 |
| 本月预计成交 | `expected_close_at` 在本月 |
| 已赢单 | stage = WON |
| 已丢单 | stage = LOST |

### 7.3 排序

默认：停滞的在前，其次按预计成交时间升序。

### 7.4 列表项展示

```
┌────────────────────────────────────────┐
│ 停滞 5 天           商务谈判            │
│ Q3 设备采购 · 星海智能科技              │
│ ¥120,000 · 预计 08-30                  │
│ [推进阶段] [记跟进] [赢单] [丢单]       │
└────────────────────────────────────────┘
```

**每条必须有可点击的动作按钮**，不是只能点进详情。

## 8. 商机详情

### 8.1 展示

| 区块 | 内容 |
|---|---|
| 概要 | 名称、客户、负责人、当前阶段、金额、预计成交时间 |
| 健康度 | 当前阶段停留天数、是否停滞 |
| 主联系人 | 姓名、手机（可拨号）、职位 |
| 阶段历史 | 每次变更：从 X 到 Y、时间、操作人、说明 |
| 跟进时间线 | 该商机相关的跟进记录（异步） |

### 8.2 动作

| 动作 | 条件 |
|---|---|
| 推进阶段 | 非终态 |
| 回退阶段 | 非终态且非首阶段，需填原因 |
| 记跟进 | 非终态 |
| 改约时间 | 有 OPEN 任务 |
| 赢单 | 阶段 = NEGOTIATION |
| 丢单 | 非终态 |
| 编辑（金额/时间/名称） | 非终态 |

## 9. 边界情况

| 情况 | 处理 |
|---|---|
| 跳级推进 | 拒绝，提示"只能推进到下一阶段" |
| 从早期阶段直接赢单 | 拒绝，提示"只有商务谈判阶段可以赢单" |
| 终态商机再操作 | 拒绝，提示"该商机已结束" |
| 预计成交时间填过去 | 创建时拒绝；已存在的商机允许（可能确实延期了） |
| 金额填负数 | 拒绝 |
| 客户被删除时有商机 | 客户删除本身被拒绝（见 [06](./06-FEATURE-CUSTOMER.md)） |
| 主联系人被删除 | 商机保留，主联系人显示"已删除"，可重新指定 |
| 并发推进阶段 | 以调用时读取的当前阶段做条件更新；一个成功，另一个返回 `CONFLICT` 且零写入 |
| 负责人被停用 | 商机保留，主管可重新分配 |

## 10. 明确不做

| 不做 | 理由 |
|---|---|
| 自定义阶段 | 见 2.3 |
| 阶段准入条件/审批 | V1 不做流程引擎 |
| 报价单 / 合同 / 订单 | 超出 CRM 范围 |
| 商机产品明细行 | V1 只有总金额 |
| 销售预测 / 加权漏斗 | 范围契约第 4 节明确不做 |
| 竞品跟踪 | 丢单原因已能记录 |
| 商机团队协作 | 一个负责人够用 |
| 商机公海/回收 | 实践反馈收益有限，V1 不做 |
