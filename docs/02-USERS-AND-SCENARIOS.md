## 0. 这份文档怎么用

功能规格（03-09）回答"这个功能怎么做"，这份文档回答"**为什么需要它**"。

写功能时如果拿不准某个细节该怎么设计，回到这里看场景——**场景里说不通的设计，就是错的设计。**

## 1. 三个角色

| 角色 | 占比 | 每天用多久 | 首要诉求 |
|---|---|---|---|
| **销售 SALES** | 80% | 多次，每次 5-20 分钟 | 别让我漏单，别浪费我时间 |
| **主管 MANAGER** | 15% | 每天 1-2 次，各 10 分钟 | 谁掉队了，哪单要黄 |
| **管理员 ADMIN** | 5% | 每周几次 | 加人、改规则 |

**产品设计优先级严格按此排序。** 三者冲突时，销售优先。

三个角色使用的是同一批线索、客户和商机，不是三套后台：

| 业务池 | 销售看到 | 主管看到 | 管理员看到 |
|---|---|---|---|
| 线索池 | 我负责的线索和下一动作 | 团队全部、未分配、超时和质量分布 | 租户全量、来源与数据质量 |
| 客户池 | 我负责的客户及当前经营状态 | 团队客户、长期未跟进和负责人负载 | 租户全量及治理状态 |
| 商机池 | 我负责的商机和推进风险 | 团队商机、阶段分布和停滞项 | 租户全量及审计结果 |

角色视图只能改变默认筛选、汇总和权限。任何一个角色完成的业务动作都必须立即反映到同一个业务池。

## 2. 销售：小陈

### 2.1 画像

- 28 岁，B2B 软件销售，入行 3 年
- 手上 40-60 条活跃线索，10 个左右商机在推
- 每天打 15-25 通电话，见 1-2 个客户
- 手机是主力设备，在外面的时间比在工位多
- **对 CRM 的态度**：以前公司用过，"填起来太烦，后来就不填了"

### 2.2 他的一天

**08:50 · 地铁上**
掏出手机，打开 CRM。**他想知道的只有一件事：今天先跟谁。**

> 工作台第一屏：「今天要跟 8 条」，第一条是李明——已超时 3 天，72 分，理由写着"填了公司名 +20，官网表单 +15"。
> 他记起来了，这条上周就该跟。

**09:30 · 到公司**
开始打电话。第一通给李明。

> 打完，点「记跟进」，选「电话」「已接通」，输入"对方在选型，下周要方案"，设下次跟进时间是周三。
> 提交。**工作台自动跳到第二条。**

**11:00 · 处理完 8 条**
工作台显示「今天的 8 条都处理完了」。他点「去看全部线索」，翻了翻还没到期的。

**14:00 · 客户现场**
在客户公司，聊完想起要记一笔。手机打开，找到这家客户，记跟进。

> **这里的关键**：390px 屏幕上，记跟进的表单必须能正常填完，按钮不能被挤出屏幕。

**16:30 · 收到通知**
手机震了一下，CRM 通知：「王芳的跟进任务已超时」。

> 他点进去，发现是上周答应今天回电的。赶紧打了。**没有这条提醒，这条线索就会停滞、无人跟进。**

**18:00 · 下班前**
看一眼商机页，两个本月要成交的，一个已经到谈判阶段，一个还卡在方案沟通。

### 2.3 他会放弃这个产品的几种情况

**每一条都是设计红线：**

| 如果 | 他会 |
|---|---|
| 打开后要自己找"今天该干嘛" | 关掉，回微信 |
| 记一条跟进要点 6 个下拉框 | 不记，数据变脏 |
| 手机上按钮被挤出屏幕 | 在外面用不了，就不用了 |
| 评分是个数字但看不出为什么 | 不信任，忽略它 |
| 超时了没人提醒 | 该产品没解决他的核心痛点 |
| 同一批线索在一屏里出现三遍 | 觉得乱，看不下去 |

### 2.4 他的原话（设计时反复回看）

> "我不需要系统教我怎么做销售，我需要它别让我漏东西。"

> "填表这事儿，超过半分钟我就不想填了。"

> "给我打分可以，但你得告诉我凭什么，不然我凭什么信？"

## 3. 主管：老周

### 3.1 画像

- 38 岁，销售总监，管 8 个销售
- 自己也背指标，也跟大单
- 每天早上和晚上各看一次团队情况
- **对 CRM 的态度**：想看过程，但不想为了看数据去催销售填表

### 3.2 他的一天

**09:00**
看一眼团队：谁的线索超时了？

> 他关心的不是"团队今天跟了多少条"，而是**"哪里出问题了"**。

**11:00**
新进了 5 条线索还没分配。他看了看，分给了两个手上单子少的销售。

**17:30**
看商机：本月能成的有几个？哪个卡住了？

> 有个商机在"方案沟通"停了 20 天。他找那个销售问了问。

### 3.3 他真正需要的

| 需要 | 不需要 |
|---|---|
| 谁的线索超时了 | 每个人今天做了几件事 |
| 哪些线索没人跟 | 完整的活动流水 |
| 哪个商机停滞了 | 精确的销售预测 |
| 谁手上活太多 | 复杂的漏斗分析 |

**V1 主管功能刻意做得薄。** 主管需要一个团队经营视图，但它只汇总三个业务池的固定口径：未分配、超时、停滞、阶段分布和负责人负载，不建设独立数据后台。

> **这是一个明确的取舍**：先做预测快照、销售贡献表、漏斗分析这类管理侧能力，往往导致销售侧闭环没打通。顺序反了。

## 4. 管理员：小张

### 4.1 画像

- 30 岁，运营/IT 兼职做系统管理
- 每周花不到 1 小时在这上面
- **诉求**：加人删人别麻烦，评分规则能自己调

### 4.2 他的场景

**新销售入职**：加账号 → 选角色 → 发登录信息。**三步以内。**

**调评分规则**：老板说"来自展会的线索质量高"，他去设置页加一条规则：来源=展会 → +15 分。保存后立即生效。

> **关键**：规则必须带"人话解释"，因为它会显示给销售看。

**装插件**：官网表单要接进来，他在设置页打开"表单获客"插件。

## 5. 关键场景剧本

以下场景是功能设计的验收依据。**功能做完后，逐个场景走一遍，走不通就是没做完。**

### 场景 1：新线索从进来到被跟进

```
① 访客在官网表单提交（表单插件）
② 系统创建线索，自动查重（手机号）
   ├─ 无重复 → 创建新线索
   └─ 有重复 → 标记疑似重复，提示人工确认
③ 系统自动评分 → 72 分，理由"填了公司名+20，官网表单+15"
④ 系统按规则分配给销售（或留在未分配池等主管分）
⑤ 销售收到通知「新线索已分配给你」
⑥ 系统创建首次响应任务，截止时间 = 分配后 24 小时
⑦ 销售打开工作台，这条线索按优先级排在队列里
⑧ 销售点击拨号 → 打完 → 记跟进 → 设下次跟进时间
⑨ 系统完成首次响应任务，生成下一步任务
```

**这条链路里，②③⑤⑥ 全部是系统自动做的，销售一步都不用管。**

### 场景 2：超时线索被救回

```
① 销售答应客户周三回电，设了跟进任务 due_at = 周三 10:00
② 周三 10:00 过去了，销售在忙别的
③ 10:05 定时任务扫描，发现超时
④ 生成通知「李明的跟进任务已超时」，销售铃铛出现红点
⑤ 销售点通知 → 跳到这条线索
⑥ 打电话 → 记跟进 → 任务完成
```

**没有第 ③④ 步，这条线索就会停滞、无人跟进。这是通知在核心而不是插件的原因。**

### 场景 3：线索转客户转商机

```
① 销售跟了三次，客户确认有采购需求
② 销售把线索标记为「已确认需求」，点「转为客户并创建商机」
   ├─ 系统按手机号查重
   ├─ 无重复 → 创建新客户和主联系人
   └─ 有重复 → 只能关联到已有客户，或修改手机号后再创建
③ 确认预填的商机名和需求说明，补预计金额、预计成交时间
④ 系统在一个事务内完成客户关联、线索转化、本次转化商机和阶段任务
⑤ 销售在商机页推进阶段：初步接触 → 方案沟通 → 商务谈判 → 赢单
```

**②的查重必须是"提示+人工确认"，不能自动合并。** 联系人手机号租户内唯一，命中后不提供“仍以相同手机号创建”的无效路径。任一步失败时，客户、联系人、线索和商机都不产生部分数据。

### 场景 4：主管发现掉队的销售

```
① 主管打开团队经营视图，看到 5 条超时线索和 2 个停滞商机
② 点击“超时线索”进入同一个线索池，自动带上团队和超时筛选
③ 发现其中 3 条属于同一个销售，再查看该销售负责的客户和商机
④ 主管重新分配需要救援的线索，并线下辅导该销售
```

团队经营视图不是一套新数据。它只显示池的聚合结果，并把主管带回对应业务池完成操作。

### 场景 5：评分不准，销售反馈

```
① 销售看到一条 85 分的线索，理由是"填了公司名+20，来自官网+15，30分钟内提交+10..."
② 但他打过电话，对方只是随便问问
③ 他点评分旁边的「不准」
④ 系统记录这次反馈
⑤ 管理员定期看反馈，调整评分规则
```

**V1 只收集反馈，不自动调权重。** 但这个入口必须有，否则评分永远无法自证。

## 6. 反场景：什么情况说明设计错了

设计评审时对照检查：

| 现象 | 说明什么 |
|---|---|
| 销售需要打开两个页面才能完成一次跟进 | 一屏干完的原则被破坏 |
| 销售问"这个分数怎么来的" | 评分理由没做好 |
| 主管为了看数据去催销售填字段 | 我们把管理需求转嫁给了销售 |
| 页面上有一句"请先选择……" | 界面在解释自己，说明设计不够直观 |
| 同一条线索在一屏出现两次 | 信息架构错了 |
| 销售说"我用微信记更快" | 我们输给了 Excel，产品失败 |
