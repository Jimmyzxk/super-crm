## 2. 角色模型

### 2.1 三个固定角色

| 角色 | 数据范围 | 典型用户 |
|---|---|---|
| `SALES` | 自己名下 | 一线销售 |
| `MANAGER` | 团队全部（= 租户内全部，V1 不做部门树） | 销售主管 |
| `ADMIN` | 租户全部 + 设置权限 | 系统管理员 |

### 2.2 V1 不做的权限能力

| 不做 | 理由 |
|---|---|
| 自定义角色 | 三个角色覆盖 95% 场景 |
| 权限矩阵配置 | 硬编码更简单可靠 |
| 部门/团队树 | V1 MANAGER 直接看租户全部 |
| 字段级权限 | 无明确需求 |
| 数据共享规则 | 一个负责人够用 |

> **为什么 MANAGER 直接看全部**：目标客户是 20-100 人公司，销售团队通常 5-20 人，一个主管管全部。做部门树是为想象中的大客户建基础设施。

### 2.3 三个业务池的角色视图契约

| 角色 | 服务端强制范围 | 默认聚合 | 动作边界 |
|---|---|---|---|
| `SALES` | `owner_user_id = 当前用户`；未分配数据不可见 | 我的到期、超时、高风险和下一动作 | 只能推进自己负责的对象，不能自行扩大范围 |
| `MANAGER` | 当前租户全部 | 未分配、超时、停滞、阶段分布和负责人负载 | 可分配、救援和推进团队对象 |
| `ADMIN` | 当前租户全部 | 来源、规则、数据质量和审计异常 | 保留权限矩阵中的治理与应急操作，不生成一套管理员业务数据 |

范围由服务端会话中的当前角色决定，客户端不能提交 `role`、任意 `tenantId` 或 `ownerUserId` 来扩大权限。角色切换或用户角色变更后，重新查询同一个业务池；对象 ID、状态和关系不得变化。

固定口径数量可以由有界查询或增量汇总提供，但必须能回到带同一筛选条件的业务池。禁止创建销售、主管、管理员专属的业务副本表或独立状态机。

### 2.5 权限校验位置

**三层，缺一不可**：

| 层 | 作用 |
|---|---|
| UI | 无权限的按钮/导航项不渲染（不是禁用，是不显示） |
| Server Action / Route Handler | 每个写操作入口校验角色 + 数据归属 |
| 数据库 RLS | 租户隔离兜底（见 [11](./11-DOMAIN-AND-DATA.md)） |

> **UI 层隐藏不是安全措施**，只是体验优化。真正的拦截在第二、三层。

## 3. 用户管理

### 3.1 用户列表

显示：姓名、邮箱、角色、状态、创建时间。

支持按姓名/邮箱搜索。

### 3.2 添加用户

| 字段 | 必填 | 校验 |
|---|---|---|
| 姓名 | ✅ | 1-50 字符 |
| 邮箱 | ✅ | 先去首尾空格并转小写；邮箱格式；**大小写不敏感地全局唯一**（跨租户，见 [11](./11-DOMAIN-AND-DATA.md) 4.2） |
| 初始密码 | ✅ | ≥ 8 位，含字母和数字 |
| 角色 | ✅ | SALES / MANAGER / ADMIN |

**添加后**：账号立即可用。V1 不做邮件邀请（需要邮件服务，是插件）。

管理员把邮箱和初始密码线下告诉新用户。

### 3.3 编辑用户

可改：姓名、角色、状态。
**不可改**：邮箱（作为登录标识，改动风险大）。

### 3.4 停用用户

`status → DISABLED`。

**副作用**：
- 立即无法登录，现有会话失效
- 名下的线索/客户/商机**保留不变**
- 不再生成新通知
- 主管可重新分配其名下数据

**不做删除**，只做停用。理由：删除会破坏历史记录的引用完整性。

### 3.5 重置密码

管理员可重置任意用户密码。重置后该用户所有会话失效。

**V1 不做**：用户自助找回密码（需要邮件服务）。

### 3.6 边界

| 情况 | 处理 |
|---|---|
| 停用最后一个 ADMIN | 拒绝，提示"至少保留一个管理员" |
| 把自己降级为 SALES | 拒绝，提示"不能修改自己的角色" |
| 停用自己 | 拒绝 |
| 邮箱仅大小写不同但已存在 | 校验拒绝，提示"该邮箱已被使用" |

## 4. 评分规则配置

### 4.1 规则列表

```
┌────────────────────────────────────────┐
│ 评分规则                      [+ 新建]  │
├────────────────────────────────────────┤
│ ✓ 填了公司名           +20    [编辑]   │
│ ✓ 来自表单             +15    [编辑]   │
│ ✓ 明确有意向           +25    [编辑]   │
│ ✓ 明确拒绝             -40    [编辑]   │
│ ✗ 有职位信息           +5     [编辑]   │
└────────────────────────────────────────┘
```

`✓` = 启用，`✗` = 停用。可拖拽排序（影响理由拼接顺序）。

### 4.2 规则编辑表单

| 字段 | 必填 | 说明 |
|---|---|---|
| 说明文案 | ✅ | **人话解释，会显示给销售看** |
| 判定字段 | ✅ | 下拉，见 [05](./05-FEATURE-SCORING.md) 4.3 |
| 判定方式 | ✅ | 下拉，见 [05](./05-FEATURE-SCORING.md) 4.4 |
| 比较值 | 条件必填 | `EXISTS`/`NOT_EXISTS` 时隐藏 |
| 分值 | ✅ | -100 ~ 100，可负 |
| 启用 | ✅ | 默认开 |

**校验**：
- `GT`/`GTE` 只能用于数值字段（`created_hour`、`activity_count`）
- `IN` 的比较值不能为空
- 说明文案 ≤ 30 字（要在卡片上显示）

### 4.3 生效规则

- 保存后**立即对新评分生效**
- **不追溯重算历史线索**
- **V1 不提供「全量重算」**（见 [12](./12-API-SPEC.md) 4.6）

### 4.4 反馈统计

显示销售的准/不准反馈汇总：

```
最近 30 天评分反馈：准 42 条 · 不准 8 条（16%）
```

**只展示，不自动调权重**（见 [05](./05-FEATURE-SCORING.md) 7.3）。

## 5. 插件管理

### 5.1 插件列表

显示已安装插件：名称、说明、状态（启用/停用）、配置入口。

V1 只有一个：**表单获客**。

### 5.2 开关

租户级开关。停用后：
- 该插件的导航项消失
- 该插件的 UI 挂载点不渲染
- 该插件不再接收事件
- **数据保留**（重新启用后还在）

### 5.3 配置

每个插件自己的配置界面，挂在 `settings.section` 挂载点。见 [13 插件契约](./13-PLUGIN-CONTRACT.md)。

## 6. 审计日志

### 6.1 记什么

所有**写操作**：

| 类别 | 示例 action |
|---|---|
| 线索 | `lead.create` `lead.assign` `lead.discard` `lead.convert` |
| 跟进 | `activity.create` |
| 任务 | `task.reschedule` |
| 客户 | `customer.create` `customer.update` `customer.delete` |
| 商机 | `opportunity.create` `opportunity.stage_change` `opportunity.win` `opportunity.lose` |
| 用户 | `user.create` `user.update` `user.disable` `user.reset_password` |
| 规则 | `score_rule.create` `score_rule.update` |
| 插件 | `plugin.enable` `plugin.disable` |

### 6.2 记录内容

| 字段 | 说明 |
|---|---|
| 操作人 | user_id |
| 动作 | action 标识 |
| 对象 | subject_type + subject_id |
| 详情 | jsonb，变更前后的关键字段 |
| 时间 | created_at |

### 6.3 查看

仅 ADMIN 可见。支持按操作人、动作类型、时间范围筛选。

**只读，不可删除、不可修改。**

### 6.4 保留期

1 年。超期自动清理。

## 7. 登录与会话

### 7.1 登录

邮箱 + 密码。

**失败处理**：
- 邮箱不存在 / 密码错误 → 统一提示"邮箱或密码不正确"（不透露哪个错）
- 账号已停用 → "该账号已停用，请联系管理员"
- **连续失败 5 次** → 锁定 15 分钟

### 7.2 会话

- JWT 存 httpOnly Cookie
- 默认有效期 7 天
- 每次请求校验，过期跳登录页

### 7.3 登出

清除 Cookie，跳登录页。

### 7.4 密码存储

bcrypt 哈希，cost factor 12。**绝不明文或可逆加密存储。**

## 8. 边界情况

| 情况 | 处理 |
|---|---|
| 唯一 ADMIN 想停用自己 | 拒绝 |
| 修改自己的角色 | 拒绝 |
| 会话中角色被改 | 下次请求时按新角色生效 |
| 会话中账号被停用 | 下次请求时拒绝并跳登录 |
| 删除还在使用的评分规则 | 允许（软删除），已有分数不变 |
| 停用插件后再启用 | 数据完好，UI 恢复 |
| 并发修改同一用户 | 后写入者生效 |

## 9. 明确不做

| 不做 | 理由 |
|---|---|
| 自定义角色 / 权限矩阵配置 | 三个角色够用 |
| 部门/团队树 | 目标客户规模不需要 |
| 邮件邀请 / 自助找回密码 | 需要邮件服务，是插件 |
| SSO / OAuth / 企微登录 | V1 不做，插件 |
| 双因素认证 | V1 不做 |
| 操作审批流 | 不做流程引擎 |
| 数据备份/恢复界面 | 运维层面，不在产品内 |
| 租户自助注册与计费 | V1 手工开通租户 |

## 10. 验收清单

- [ ] 权限矩阵每一格都被实现且可验证
- [ ] SALES 只能看到自己的数据（线索/客户/商机各验一次）
- [ ] MANAGER / ADMIN 读取的是同一业务池的租户范围，不存在角色业务副本
- [ ] 客户端伪造 role / tenantId / ownerUserId 不能扩大查询范围
- [ ] 无权限的按钮和导航项**不渲染**
- [ ] Server Action 层独立校验权限（绕过 UI 直接调用被拒绝）
- [ ] 停用最后一个 ADMIN 被拒绝
- [ ] 修改自己的角色被拒绝
- [ ] 停用用户后立即无法登录，现有会话失效
- [ ] 停用用户后其名下数据保留
- [ ] 评分规则改完立即对新评分生效，历史分数不变
- [ ] 评分规则说明文案会显示在销售看到的理由里
- [ ] 登录失败统一提示，不透露是邮箱错还是密码错
- [ ] 连续失败 5 次锁定 15 分钟
- [ ] 密码 bcrypt 存储，数据库里查不到明文
- [ ] 所有写操作都有审计日志
- [ ] 审计日志不可删改
