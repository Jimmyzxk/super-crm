# 功能规格：AI 销售教练与销冠打法

版本：v1.0 · 2026-08-14

---

## 1. 目标

系统不只保存 CRM 事实，还要回答三个问题：

1. **这笔业务现在缺什么？**
2. **销售下一步应该做什么、何时做？**
3. **这个建议来自哪些已确认事实或团队打法？**

最终目标不是生成漂亮文案，而是把优秀销售的推进节奏、关键信息收集和异议处理方式变成团队可复用的行动建议。

## 2. 两层判断，禁止混成一个分数

| 层 | 回答的问题 | 输出 |
|---|---|---|
| 线索质量 | 值不值得优先投入 | 0-100、等级、正负证据、缺失信息 |
| 推进健康度 | 当前推进是否正确 | 正常/关注/高风险、风险原因、下一步、建议截止时间 |

线索资料填得完整不代表意向强；商机金额高也不代表推进健康。UI 必须分别展示，不能只给一个“AI 分”。

## 3. 自动质检触发

以下事实写入后，同一事务提交业务事实，再同步生成或刷新规则版分析：

- 新建或更新线索；
- 写入线索、客户或商机跟进；
- 标记需求、转客户、创建商机；
- 商机阶段推进、回退、改约、赢单或丢单；
- 定时扫描发现任务超时或阶段停滞。

分析失败不得回滚业务事实。失败时保留上一次成功结果并标记“待刷新”，不得显示伪造的新建议。

质检没有独立的“AI 客户库”。它只读取三个业务池及其过程记录：

- 线索质量和首次推进建议写回线索上下文；
- 客户经营建议由客户及其活跃商机事实组合得出，不创建独立客户阶段；
- 商机健康度、赢单复盘和打法推荐写回商机上下文；
- 单次计算只读取当前对象和有界事实窗口，禁止扫描整个租户活动历史；
- 跨池事实通过 `lead_conversions` 和 `customer_id` 追溯，不复制整份对象数据。

## 4. V1 质检规则

每条规则必须输出 `code`、人话原因、证据引用和建议动作：

| code | 触发条件 | 建议 |
|---|---|---|
| `MISSING_DECISION_MAKER` | 方案阶段仍未记录决策人 | 确认决策人及其关注点 |
| `MISSING_BUDGET` | 方案阶段仍无预算信息 | 补充预算范围和审批路径 |
| `MISSING_TIMELINE` | 已确认需求但无计划时间 | 确认采购或上线时间 |
| `NO_NEXT_STEP` | 最近跟进没有下一步时间 | 与客户确认下一动作并设提醒 |
| `FOLLOWUP_OVERDUE` | OPEN 任务已超时 | 今天优先联系并更新结果 |
| `STAGE_STALLED` | 超过阶段 SLA 且无有效推进 | 复核阻塞点，推进或降级/丢单 |
| `WEAK_FOLLOWUP` | 连续两次摘要过短或只有“已联系”等无信息内容 | 补记客户反馈、异议和下一步 |
| `POSITIVE_SIGNAL` | 最近结果为有意向且下一步明确 | 按约定时间推进，不提前骚扰 |

V1 先用确定性规则保证可测试、可解释、无模型也可运行。接入模型后，只允许做事实摘要、表达改写和跨样本归纳，不得改变规则命中事实。

### 4.1 智能跟进提炼与结构化辅助（30 秒极速录入）

为解决销售在移动端或快速通话后不愿逐项点击下拉框的问题，系统提供**跟进文本智能辅助解析器**：

1. **输入**：一段非结构化的沟通速记文本（或语音转文字输入）。
2. **输出结构化建议**：
   - `suggestedType`：沟通方式（`CALL`/`MEETING`/`VISIT`/`MESSAGE`/`NOTE`）；
   - `suggestedOutcome`：沟通结果（`CONNECTED`/`NO_ANSWER`/`REFUSED`/`INTERESTED`）；
   - `detectedObjections`：检测到的异议或需求标签（如“预算不足”、“竞品对比”、“决策链长”）；
   - `suggestedNextFollowUpDays`：建议下次跟进间隔天数（如客户说“下周二联系”，自动换算对应绝对时间）；
   - `cleanSummary`：清洗后的标准化跟进摘要（去除多余口语词，保留核心事实）。
3. **人工确认边界**：解析结果作为前端界面的“预填建议”，销售一键确认或微调后写入数据库，系统不绕过销售直接自动落库。

### 4.2 大模型增强与零风险降级契约

当系统配置了大模型接口（LLM API）时，用于增强摘要质量与跨样本归纳，但必须满足以下四条硬性契约：

1. **多租户数据脱敏**：发送至外部模型的 Prompt 必须抹除租户敏感标识与手机号中间 4 位，仅包含业务事实语义；
2. **零依赖安全降级**：当未配置模型密钥、调用超时（>3秒）或模型返回格式异常时，系统 **100% 自动降级为内置启发式规则解析器**，保证销售录入与系统运行无感知中断；
3. **结构化输出约束**：模型调用必须采用 JSON 严格 Schema 约束，严禁输出不受控的自由对话文本；
4. **禁止越权修改事实**：模型仅生成建议、摘要与推荐，禁止自动改动线索状态、客户所有者或商机阶段。

## 5. 建议对象与人工边界

每条建议包含：对象、状态、标题、摘要、建议动作、建议截止时间、证据、来源规则或打法版本、置信说明、生成时间和有效期。

状态：`OPEN → ACCEPTED / DISMISSED / EXPIRED`。

- 采纳建议：由销售确认后创建或改约任务；不得自动改线索状态或商机阶段，客户经营状态只能随商机事实派生。
- 忽略建议：必须选择“不适用 / 已处理 / 信息错误 / 其他”，用于评估建议质量。
- 新事实进入后，旧建议不再成立则标记 `EXPIRED`，保留审计记录。
- 不展示模型思维过程，只展示可核验的业务证据。

## 6. 赢单复盘

商机变为 `WON` 后自动生成复盘草稿，内容来自不可变的业务时间线：

- 从创建到赢单总周期、各阶段停留时间；
- 首次响应耗时、跟进次数和平均间隔；
- 关键阶段转换前的最近一次有效跟进；
- 已记录的客户异议、需求、预算、决策人和下一步；
- 赢单原因、金额和适用客户特征；
- 数据缺失与不能下结论之处。

单个赢单只能叫“赢单样本”，不能自动叫“最佳实践”。

只有生成完成且至少包含一条事实证据的草稿可以提交主管审核。生成失败不回滚赢单，草稿保留失败时间和尝试次数，并按至少 5 分钟冷却自动重试；失败或空草稿不得进入审核终态。

## 7. 团队打法发布门槛

主管可以把多个同类赢单样本合并为打法草稿。发布为团队打法必须同时满足：

1. 至少 3 个已确认赢单样本；
2. 明确适用范围和不适用范围；
3. 每个结论可追溯到样本事实；
4. 主管填写审核理由并发布版本；
5. 发布后不可原地覆盖，只能创建新版本。

打法内容固定为：适用场景、关键检查点、推荐节奏、有效动作、常见风险、证据样本数、版本和审核人。

## 8. 复用与反馈

商机进入新阶段或质检触发时，系统按阶段和客户特征匹配**已发布**打法，最多推荐 1 条最相关打法，并明确显示“基于 N 个赢单样本”。

销售可以反馈：`有帮助 / 无帮助 / 不适用`。系统统计采纳率、按时完成率和后续阶段推进率，但 V1 不自动改写打法，也不声称因果提升。

### 8.1 销冠打法多维加权匹配算法

当商机进入阶段或质检触发时，系统从租户已发布的打法库（`sales_playbooks` where `status = 'PUBLISHED'`）中计算匹配得分 $Score$：

$$Score = W_{stage} + W_{industry} + W_{size} + W_{region} + W_{samples}$$

1. **阶段硬门槛**：`targetStage` 必须与商机当前阶段严格一致（不一致则 $Score = -1$，直接排除）；
2. **行业匹配（权重 40 分）**：
   - 命中 `applicableIndustries` $\rightarrow +40$ 分；
   - 命中 `excludedIndustries` $\rightarrow$ 立即排除（得分清零）；
   - 未指定行业（通用打法） $\rightarrow +10$ 分；
3. **客户规模匹配（权重 30 分）**：
   - 命中 `applicableCustomerSizes` $\rightarrow +30$ 分；
   - 命中 `excludedCustomerSizes` $\rightarrow$ 立即排除；
   - 通用规模 $\rightarrow +10$ 分；
4. **地域匹配（权重 15 分）**：
   - 命中 `applicableRegions` $\rightarrow +15$ 分；
   - 命中 `excludedRegions` $\rightarrow$ 立即排除；
5. **样本数量加成（权重 15 分）**：
   - 基于样本数 $N$ 增益：$\min(15, \lfloor N / 2 \rfloor \times 3)$，样本越充足置信度越高；
6. **推荐输出**：按得分最高者择优推荐 1 条，并标明匹配维度与样本数。

## 9. 页面要求

- `/today`：按优先级展示“现在该做什么”，每项包含原因、建议动作和完成入口。
- 线索池/详情：质量、缺失信息和首次推进建议与当前对象同屏。
- 客户池/详情：显示由客户和活跃商机推导的经营状态，不维护独立 AI 客户副本。
- 商机池/详情：顶部必须同时展示阶段、健康度、下一步和风险；阶段历史与跟进合并为一条经营时间线。
- `/playbooks`：主管审核打法，销售查看已发布打法及适用范围。
- AI 建议不做独立技术后台；建议必须出现在销售正在工作的对象页面和今日队列。

## 10. 验收

- [ ] 跟进未设下一步时，立即出现有证据的建议，可一键创建任务
- [ ] 商机超过阶段 SLA 时显示高风险及具体原因
- [ ] 新事实使建议失效时，旧建议变为 `EXPIRED`
- [ ] AI 或规则失败不影响跟进和阶段推进
- [ ] 赢单后自动生成可追溯复盘草稿
- [ ] 少于 3 个样本不能发布团队打法
- [ ] 已发布打法可在相似商机阶段被推荐并显示样本数
- [ ] 建议采纳、忽略和结果反馈均留痕
- [ ] 没有模型密钥时全部核心规则仍可运行

## 11. 成功指标

内部验收和真实试用分别衡量，不能用自动化测试代替用户结果。

| 指标 | 内部验收 | 真实销售连续试用 5 天 |
|---|---|---|
| 有下一步时间的有效跟进占比 | 测试场景 100% 可记录 | 相比试用第 1 天提高，目标 ≥ 80% |
| 超时或停滞识别 | 规则测试 100% 命中 | 已发生风险中 ≥ 90% 在页面可见 |
| 建议可解释 | 每条建议至少 1 条事实证据 | 销售能在 10 秒内说清“为什么建议” |
| 建议行动价值 | 采纳后可创建任务并留痕 | 采纳率 ≥ 30%，不适用原因可统计 |
| 赢单复盘完整性 | 周期、阶段、跟进和缺失项均可生成 | 主管无需查原始表即可完成初审 |
| 打法可信度 | 少于 3 个样本无法发布 | 销售能看到样本数、适用和不适用范围 |

不以 AI 文案长度、模型调用次数或建议数量作为成功指标。

## 12. 待验证假设

1. 销售愿意补充“下一步”和关键事实，只要记录过程不超过 30 秒。
2. 基于规则的及时提醒比泛化聊天助手更能改变推进动作。
3. 主管愿意审核赢单复盘，但不会维护复杂知识库。
4. 3 个同类样本足够形成初版观察打法，但仍不足以声称因果最佳实践。
5. API 单向进线能覆盖首批集成需求，暂不需要双向 CRM 同步。

每条假设必须在真实试用中记录证据。被否定时修改规则或范围，不能通过增加基础设施掩盖。

## 13. 分阶段发布

| 阶段 | 内容 | 明确不含 |
|---|---|---|
| A 智能底座 | 确定性质检规则、建议状态、今日/对象页展示、采纳与忽略 | 模型调用、打法库 |
| B 多渠道进线 | 外部 API 来源密钥、幂等、限流、统一创建服务 | 双向同步、渠道 ROI |
| C 赢单沉淀 | 赢单复盘、3 样本门槛、主管审核、版本化打法、反馈 | 向量库、自动调优 |
| D 模型增强 | 在有真实样本后增强摘要和跨样本归纳 | 自动改阶段、自动发客户消息 |

每阶段独立迁移、测试、浏览器验收和提交；上一阶段未通过不得开始下一阶段。
