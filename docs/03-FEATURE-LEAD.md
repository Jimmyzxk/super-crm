# 功能规格：线索管理

版本：v1.0 · 2026-08-11
从属于：[00-SCOPE-CONTRACT.md](./00-SCOPE-CONTRACT.md) · 场景依据：[02-USERS-AND-SCENARIOS.md](./02-USERS-AND-SCENARIOS.md)

---

## 1. 这个模块做什么

线索（Lead）是**还没确认价值的潜在客户**。它的生命周期是：进来 → 被分配 → 被跟进 → 转成客户 / 被丢弃。

本模块负责：**录入、去重、分配、状态流转、检索**。

> 跟进动作本身见 [04 跟进与任务](./04-FEATURE-FOLLOWUP.md)，评分见 [05 智能评分](./05-FEATURE-SCORING.md)。

`/leads` 是统一线索池，不是“销售私有列表”。销售、主管和管理员读取同一张事实表，只根据角色应用不同的默认范围、聚合和动作权限。

## 2. 核心概念

### 2.1 为什么线索和客户要分开

| | 线索 Lead | 客户 Customer |
|---|---|---|
| 含义 | 可能有价值，还没确认 | 已确认有价值 |
| 可能重复 | 是 | 否（同一手机号只有一个） |
| 可能无效 | 是 | 否 |
| 谁创建 | 系统（表单/导入）或销售 | **只能由销售确认后创建** |

**关键规则：线索转客户必须由人确认，系统不自动转。**

原因：自动转会把垃圾数据变成客户，污染客户库。销售打过电话才知道对方是不是真客户。

### 2.2 V1 不做四层身份归一

上一个项目做了 Lead → Person → Contact → Customer 四层归一 + 合并冲突队列。设计是对的，但对 V1 过重。

**V1 简化为**：手机号查重 + 人工确认。见第 4 节。

## 3. 线索录入

### 3.1 四种核心来源

| 来源 | source 值 | 谁触发 | 是否 V1 |
|---|---|---|---|
| 手工录入 | `manual` | 销售/主管；管理员仅应急录入 | ✅ |
| CSV 导入 | `import` | 主管/管理员 | ✅ |
| 表单提交 | `form:<formId>` | 访客 | ✅（表单插件） |
| 外部 API | `api:<sourceKey>` | 已授权系统 | ✅ |

四个入口必须调用同一个核心创建服务，执行相同的字段校验、手机号查重、来源记录和自动分析。API 不能绕过业务校验直接写表。

### 3.5 外部 API 录入

每个租户可创建多个来源密钥。调用方使用 `Authorization: Bearer <token>`，token 只在创建时显示明文，数据库仅保存 hash。

- 必须携带 `Idempotency-Key`，同一来源 24 小时内重复请求返回首次结果；
- 单密钥默认 60 次/分钟，超过返回 429；
- `source = api:<sourceKey>`，并保存外部记录号、接收时间和原始来源标签；
- 手机号命中进行中线索时仍创建并标记疑似重复，不自动覆盖已有资料；
- 禁止通过 API 指定租户、负责人、分数、状态或商机；这些由服务端上下文和业务规则决定。

### 3.2 手工录入

**入口**：线索页右上角「+ 新建线索」

**字段**：

| 字段 | 必填 | 校验 | 失败文案 |
|---|---|---|---|
| 联系人姓名 | ✅ | 1-50 字符 | 请填写联系人姓名 |
| 手机号 | ✅ | 中国手机号格式 `^1[3-9]\d{9}$` | 请填写正确的手机号 |
| 公司名称 | ❌ | ≤ 100 字符 | 公司名称不超过 100 字 |
| 邮箱 | ❌ | 标准邮箱格式 | 邮箱格式不正确 |
| 职位 | ❌ | ≤ 50 字符 | — |
| 备注 | ❌ | ≤ 500 字符 | 备注不超过 500 字 |
| 负责人 | 条件必填 | SALES 固定自己；MANAGER 可选 active SALES/MANAGER，默认自己；ADMIN 必须选 active SALES/MANAGER | 请选择负责人 |

**提交后**：
1. 手机号查重（见第 4 节）
2. 创建线索，`status = NEW`；SALES / MANAGER 默认归当前用户，ADMIN 必须指定一名 active 的 SALES/MANAGER 负责人
3. **自动评分**（见 [05](./05-FEATURE-SCORING.md)）
4. 有负责人时创建首次响应任务，`due_at = now + 24 小时`；无负责人时留在未分配池，不建任务
5. 跳转到该线索详情

### 3.3 CSV 导入

**入口**：线索页「导入」按钮

**流程**：

```
① 上传 CSV
② 系统解析，展示预览（前 50 行）
③ 展示三类问题：
   - 格式错误行（手机号不合法、缺必填）
   - 疑似重复行（手机号已存在）
   - 可正常导入行
④ 用户选择：跳过重复 / 全部导入
⑤ 确认导入
⑥ 展示结果：成功 N 条、跳过 M 条、失败 K 条
```

**CSV 格式**：

| 列名 | 必填 |
|---|---|
| 姓名 | ✅ |
| 手机号 | ✅ |
| 公司 | ❌ |
| 邮箱 | ❌ |
| 职位 | ❌ |
| 备注 | ❌ |

**约束**：
- 单次最多 1000 行
- 文件大小 ≤ 2MB
- 编码支持 UTF-8 和 GBK（中文 Excel 导出常见）

**导入后**：所有成功行自动评分，但**不自动分配**（留在未分配池，由主管分配）。

### 3.4 表单提交

由表单获客插件产生，见 [13 插件契约](./13-PLUGIN-CONTRACT.md)。

核心行为：查重 → 创建 → 评分。
差别：`source = form:<formId>`，`owner_user_id = null`（等分配）。

**不创建首次响应任务。**

> **为什么**：任务的 `assignee_user_id` 非空（见 [11](./11-DOMAIN-AND-DATA.md) 4.7），
> 而此时线索还没有负责人。给"没人负责的线索"设超时提醒也没有意义——超时了通知谁？
>
> 任务在**分配时**创建（见 5.2），`due_at = 分配时间 + 24 小时`。
> 首次响应时限从"有人接手"开始算，这也更公平。

CSV 导入同理：导入的线索不分配、不建任务。

## 4. 去重规则

### 4.1 判定依据

**只按手机号判重。** 不做姓名模糊匹配、不做公司名匹配。

理由：手机号是 B2B 场景下最可靠的唯一标识。姓名重名多，公司名写法不一（"星海科技"vs"星海智能科技有限公司"），模糊匹配容易误判，误判的代价比漏判大。

### 4.2 查重范围

在**当前租户内**查找 `contact_phone` 相同且 `status != DISCARDED` 的线索。

### 4.3 命中后的处理

**绝不自动合并。** 三种场景，三种处理：

| 场景 | 处理 |
|---|---|
| 手工录入命中 | 弹提示「该手机号已存在线索：李明（星海科技），负责人张三」，提供两个选择：「仍然创建」/「查看已有线索」 |
| CSV 导入命中 | 在预览里标记为"疑似重复"，用户决定跳过还是导入 |
| 表单提交命中 | **自动创建**，但标记 `is_possible_duplicate = true`，在列表里显示"疑似重复"标签 |

> **为什么表单提交不拦截**：访客不知道自己重复提交了，拦截会导致线索丢失。宁可多一条待处理，不可少一条线索。

### 4.4 疑似重复的后续处理

线索详情页显示"疑似重复"提示 + 已有线索链接。销售可以：
- 「不是重复」→ 清除标记
- 「合并到已有线索」→ 把本条的跟进记录挪到已有线索，本条状态置 `DISCARDED`

**合并是人工动作，且不可逆（记审计日志）。**

## 5. 线索分配

### 5.1 分配方式

V1 只做**手工分配**，不做自动分配规则。

| 场景 | 谁能分配 |
|---|---|
| 未分配线索 → 某销售 | MANAGER / ADMIN |
| 销售 A 的线索 → 销售 B | MANAGER / ADMIN |
| 销售给自己认领未分配线索 | **V1 不做** |

> **为什么不做自动分配**：自动分配规则（轮流、按负载、按地域）是典型的"看起来必要，实际每家都不同"的能力。等真实客户提出再说。

### 5.2 分配后

1. `owner_user_id` 更新
2. 生成通知给新负责人：「新线索已分配给你」
3. 若无进行中的首次响应任务，创建一个，`due_at = now + 24 小时`
4. 记审计日志

### 5.3 批量分配

主管可在线索列表勾选多条 → 「分配给」→ 选销售 → 确认。

**上限一次 50 条**，超过提示分批操作。

## 6. 线索状态

### 6.1 状态全集

| 状态 | 含义 | 谁能进入 |
|---|---|---|
| `NEW` | 刚创建，还没联系过 | 系统（创建时） |
| `CONTACTED` | 已联系过至少一次 | 系统（首次跟进后自动） |
| `QUALIFIED` | 确认有需求，值得转客户 | 销售（手动标记） |
| `CONVERTED` | 已转为客户 | 系统（转客户时） |
| `DISCARDED` | 无效/放弃 | 销售（手动） |

### 6.2 合法转换

```
NEW ──────► CONTACTED ──────► QUALIFIED ──────► CONVERTED
 │              │                  │
 └──────────────┴──────────────────┴──────────► DISCARDED
```

**规则**：
- `NEW → CONTACTED`：**系统自动**，第一条跟进记录写入时触发
- `CONTACTED → QUALIFIED`：销售手动，需填写"确认了什么需求"
- `QUALIFIED → CONVERTED`：转客户时系统自动
- 只有 `QUALIFIED` 且已有负责人的线索可转客户；转化必须同时创建本次转化商机，完整原子规则见 [06](./06-FEATURE-CUSTOMER.md) 第 3 节
- 任意状态 → `DISCARDED`：销售手动，**必填放弃原因**
- `CONVERTED` 是终态，不可再变
- `DISCARDED` 可恢复为 `NEW`（由 MANAGER 操作；有负责人时重建首次响应任务；记审计）
- 每次合法转换与创建都写入状态记录，包含转换前后状态、原因、操作者和时间；与业务写入同事务提交
- 非法转换不改变线索，也不写状态记录

**非法转换直接拒绝并报错**（错误码见 [12 接口规格](./12-API-SPEC.md)）。

### 6.3 放弃原因（枚举 + 补充说明）

| 枚举值 | 显示 |
|---|---|
| `NO_NEED` | 没有需求 |
| `NO_BUDGET` | 没有预算 |
| `WRONG_CONTACT` | 联系人不对 |
| `INVALID_INFO` | 信息无效（空号、错号） |
| `COMPETITOR` | 选了竞品 |
| `OTHER` | 其他（必填补充说明） |

## 7. 线索列表与检索

### 7.1 默认视图

**销售**：线索池默认筛选“我负责的”，按优先级排序（排序规则见 [04](./04-FEATURE-FOLLOWUP.md) 第 5 节）
**主管**：线索池默认团队范围，顶部显示未分配、超时、高分和疑似重复的固定口径数量
**管理员**：线索池默认租户范围，增加来源和数据质量筛选，不增加销售推进动作

三种视图必须共享同一个查询服务和同一套状态定义，禁止为角色复制线索表或单独维护计数。

### 7.2 筛选

| 筛选项 | 选项 |
|---|---|
| 全部 | 默认 |
| 超时 | 有超时任务的 |
| 高分 | score ≥ 70 |
| 未分配 | owner_user_id is null（仅 MANAGER/ADMIN 可见） |
| 疑似重复 | is_possible_duplicate = true |

**筛选是切换视图，不是并列列表。** 一条线索在当前视图里只出现一次。

### 7.3 搜索

搜索框支持：姓名、手机号、公司名。**前缀匹配 + 手机号全匹配。**

搜索是主要入口，**不折叠、不隐藏**。

### 7.4 排序

默认按优先级（见 04 第 5 节）。可切换为：
- 创建时间（新→旧）
- 评分（高→低）

### 7.5 分页

游标分页，每页 20 条，「加载更多」按钮。

**不做页码跳转** —— 销售不会跳到第 7 页。

列表首屏只能读取当前状态、当前评分、负责人、下一任务时间和最近跟进时间；跟进全文、状态历史和审计记录进入详情后再按游标加载。禁止列表请求 JOIN 全量历史或执行无条件 `COUNT(*)`。

## 8. 线索详情

### 8.1 展示内容

```
基本信息   姓名、手机、邮箱、公司、职位、来源、创建时间
评分       分数 + 理由 + 准/不准反馈按钮
当前状态   状态标签 + 负责人
下一步     当前任务 + 截止时间 + 超时标记
跟进记录   时间线（异步加载）
状态记录   状态转换时间线（前后状态、原因、操作者、时间）
疑似重复   若有，显示提示和关联线索
```

### 8.2 可执行动作

| 动作 | 谁能做 | 结果 |
|---|---|---|
| 记跟进 | 负责人 / MANAGER / ADMIN | 见 [04](./04-FEATURE-FOLLOWUP.md) |
| 设下次跟进 | 同上 | 更新/创建任务 |
| 标记为已确认需求 | 同上 | status → QUALIFIED |
| 转客户并创建商机 | 同上；仅 `QUALIFIED` 且已有负责人 | 见 [06](./06-FEATURE-CUSTOMER.md) |
| 放弃 | 同上 | status → DISCARDED，必填原因 |
| 编辑基本信息 | 同上 | 手机号变更需重新查重 |
| 重新分配 | MANAGER / ADMIN | 见 5.2 |

## 9. 边界情况

| 情况 | 处理 |
|---|---|
| 手机号改成了另一个已存在的号 | 重新查重，命中则提示 |
| 线索已转客户，又收到同手机号表单提交 | 创建新线索，标记疑似重复，提示已关联客户 X |
| 负责人被停用 | 线索保留，`owner_user_id` 不变，主管可重新分配 |
| 导入的 CSV 有 BOM 头 | 自动识别并剥离 |
| 导入 CSV 手机号是科学计数法（Excel 常见） | 解析失败，在预览里标为格式错误 |
| 同一手机号同时有多条 DISCARDED 线索 | 查重时忽略 DISCARDED，允许新建 |
| 并发：两个人同时给同一线索分配 | 后写入者覆盖，记审计日志（V1 不做乐观锁） |

## 10. 明确不做

| 不做 | 理由 |
|---|---|
| 自动分配规则 | 每家不同，等真实需求 |
| 线索公海 / 抢单 | 复杂度高，V1 用手工分配够 |
| 姓名/公司模糊查重 | 误判代价大于漏判 |
| 线索评级（A/B/C） | 评分已经承担这个作用 |
| 自定义字段 | 见范围契约第 4 节 |
| 线索转移审批流 | V1 不做流程引擎 |

## 11. 验收清单

- [ ] 手工录入：必填校验、手机号格式校验、提示文案正确
- [ ] 手工录入命中重复：正确提示且能选择继续或查看
- [ ] CSV 导入：预览正确区分正常/重复/错误三类
- [ ] CSV 导入：UTF-8 和 GBK 都能正确解析中文
- [ ] 所有入口创建后自动评分；有负责人时自动建首次响应任务，未分配时不建、分配后补建
- [ ] ADMIN 应急录入必须指定 active 的 SALES/MANAGER 负责人，不能把线索或任务分配给自己
- [ ] 状态机：每条合法转换可执行，非法转换被拒绝
- [ ] 每次合法状态转换都留痕，非法转换零写入，跨租户不可见
- [ ] 线索详情展示完整跟进时间线与状态记录，按时间倒序
- [ ] 放弃必填原因，选"其他"时必填补充说明
- [ ] 分配后生成通知，且新负责人能收到
- [ ] 筛选：一条线索在当前视图只出现一次
- [ ] 搜索：姓名前缀、手机号全匹配都能搜到
- [ ] 销售只能看到自己的，主管能看到团队的（租户隔离测试另见 [16](./16-TEST-PLAN.md)）
