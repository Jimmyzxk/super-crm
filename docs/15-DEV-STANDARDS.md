## 1. 三条铁律

写在最前面，因为这三条是上一个项目失败的直接原因：

### 铁律 1：范围

> 任何不在 [00 范围契约](./00-SCOPE-CONTRACT.md) 第 3 节的功能，
> 进入前必须过第 6 节准入规则，并在变更日志留痕。

**"顺手做了"是范围失控的唯一机制。** 上个项目的文档白纸黑字写着"V1 表单不做条件跳转"，一个月后代码里有了条件显示和跳转——没人决定要做，它就是被顺手做出来的。

### 铁律 2：验证

> 每个阶段结束必须 `typecheck` + `test` + **浏览器实测**，三者缺一不算完成。

上个项目有 3000+ 行代码从未跑过 typecheck，问题堆积到无法定位。**静态检查证明不了代码能跑。**

### 铁律 3：提交

> 阶段完成即提交，不攒大提交。数据库迁移与使用它的代码在同一次提交。

上个项目 444 个源文件从未进入版本控制，没有任何回滚点。

## 2. TypeScript

### 2.1 编译配置（不可放宽）

```jsonc
{
  "strict": true,
  "noUncheckedIndexedAccess": true,   // 数组下标返回 T | undefined
  "noImplicitOverride": true,
  "noUnusedLocals": true,
  "noUnusedParameters": true,
  "verbatimModuleSyntax": true
}
```

### 2.2 禁止

| 禁止 | 替代 |
|---|---|
| `any` | `unknown` + 类型收窄 |
| `as` 强制断言 | 类型守卫函数 |
| `@ts-ignore` | `@ts-expect-error` + 注释说明原因 |
| 非空断言 `!` | 显式判空 |

**例外**：第三方库类型缺陷时可用 `as`，但必须写注释说明。

### 2.3 类型放哪

| 类型 | 位置 |
|---|---|
| 数据库行类型 | 从 Drizzle schema 推导，不手写 |
| Action 入参 | Zod schema 推导（`z.infer`） |
| 模块内部类型 | `core/<模块>/types.ts` |
| 跨模块共享类型 | `src/types/` |

**不要手写与数据库重复的接口。**

## 4. 代码组织

### 4.1 文件规模上限

| 类型 | 上限 | 超了怎么办 |
|---|---|---|
| 组件 | 300 行 | 拆子组件 |
| Action 文件 | 400 行 | 按操作拆分 |
| 规则文件 | 300 行 | 按领域拆分 |

> 上个项目有 2900 行的单个 Vue 组件和 2680 行的视图文件。**那种文件没人能安全修改。**

### 4.2 函数

- 单个函数 ≤ 50 行
- 参数 ≥ 4 个时改用对象参数
- 嵌套 ≤ 3 层，超了提前 return

### 4.3 业务规则必须是纯函数

```
core/<模块>/rules.ts   ← 纯函数，无 IO，单测直接覆盖
core/<模块>/actions.ts ← 编排：校验 → 调 rules → 写库
```

状态机、评分计算、超时判定都放 `rules.ts`。**这样它们可以被穷举测试。**

### 4.4 三个业务池的查询边界

- 线索池、客户池、商机池共用各自唯一的查询服务；角色只注入服务端数据范围、固定聚合和动作权限；
- 列表使用排序字段 + `id` 的游标分页，禁止深层 `OFFSET`；
- 列表只返回当前事实和固定摘要，禁止 JOIN 全量活动、状态历史或审计记录；
- 禁止无条件 `COUNT(*)`、每个标签各扫一次全表和逐行补数据的 N+1；
- 详情历史按 `tenant_id + object_id` 限定并游标分页，默认 20 条；
- 新查询必须在代表性容量数据上检查 `EXPLAIN (ANALYZE, BUFFERS)`，索引依据写入迁移或提交说明。

角色视图需要新字段时，先判断它属于当前事实、过程摘要还是固定分析指标。禁止为了页面方便把整段历史复制回池主表，也禁止创建角色专属业务表。

## 5. 注释

### 5.1 写什么

| 写 | 不写 |
|---|---|
| **为什么**这么做 | 代码已经说清的"做了什么" |
| 非显而易见的约束 | 逐行翻译代码 |
| 踩过的坑 | 无信息量的 JSDoc |

### 5.2 例子

```ts
// ✅ 好：解释为什么
// set_config 必须在事务内，否则变量设在连接 A、查询跑在连接 B，RLS 拿不到 tenant_id。
await tx.execute(sql`select set_config('app.tenant_id', ${tenantId}, true)`)

// ❌ 坏：翻译代码
// 设置 tenant_id
await tx.execute(...)
```

### 5.3 注释语言

**中文。** 团队母语，表达更准确。

## 6. Git

### 6.1 提交粒度

**一个可工作的改动一次提交。** 不攒大提交。

判据：这次提交能不能单独描述清楚？能不能单独回滚？

### 6.2 提交信息格式

```
<type>(<scope>): <一句话说清做了什么>

<为什么这么做，如果不显然>
```

**type**：`feat` / `fix` / `refactor` / `docs` / `test` / `chore`

例子：

```
feat(lead): 线索创建后自动评分

上个项目评分只能手动触发，导致新线索永远没有分数。
这里在 createLead 的事务内同步调用评分，失败不阻断创建。
```

### 6.3 必须同提交的东西

| 一起提交 | 原因 |
|---|---|
| 迁移 + 使用它的代码 | 否则 checkout 到中间状态会崩 |
| 功能 + 它的测试 | 否则测试永远"下次再补" |
| 接口变更 + 所有调用点 | 否则编译不过 |

### 6.4 分支

V1 单人开发，**直接在 main 上提交**。有第二个人时再引入分支流程。

### 6.5 不提交什么

`.env`、`node_modules/`、`.next/`、构建产物、IDE 配置、`.DS_Store`。

**`.env.example` 必须提交且与代码同步。**

## 8. 安全

### 8.1 密码

- bcrypt，cost factor 12
- **绝不**明文、可逆加密、MD5/SHA
- 日志、错误信息、API 响应里**绝不**出现密码或哈希

### 8.2 会话

- JWT 存 httpOnly + Secure + SameSite=Lax Cookie
- 有效期 7 天
- 停用用户 / 重置密码时使会话失效

### 8.3 SQL 注入

- 一律用 Drizzle 的参数化查询
- **禁止字符串拼接 SQL**
- 迁移文件里的 `unsafe` 执行仅限受信任的迁移内容

### 8.4 租户越权（最高优先级）

| 措施 | 说明 |
|---|---|
| 所有查询走 `withTenant()` | ESLint 强制 |
| 应用连接用非 owner 角色 | 否则 RLS 静默失效 |
| 每张业务表有 RLS 策略 + FORCE | 迁移里同时写 |
| 每张业务表有跨租户泄漏测试 | 见 [16](./16-TEST-PLAN.md) |
| 跨租户访问返回 `NOT_FOUND` | 不泄露"存在但不属于你" |

### 8.5 敏感信息脱敏

日志和非详情页展示手机号时脱敏：`138****1001`。

### 8.6 公开接口

表单提交等公开 Route Handler：
- 限流（同 IP 每分钟 10 次）
- 不回传内部 ID
- 入参严格校验

## 9. 错误处理

### 9.1 Server Action

业务失败返回 `{ ok: false, code, message }`，**不抛异常**。
只有真正的系统故障（数据库断连等）才抛。

### 9.2 用户可见文案

| 好 | 坏 |
|---|---|
| 该手机号已存在 | DUPLICATE_PHONE |
| 当前状态不允许此操作 | Invalid state transition |
| 系统出错了，请稍后重试 | Internal Server Error: ECONNREFUSED |

**绝不把技术细节暴露给用户**，但要记进日志。

### 9.3 前端

- 提交失败**保留已填内容**
- 提供重试按钮
- 加载失败显示原因 + 重试

## 10. 代码评审清单

自查或互查时逐条过：

**范围**
- [ ] 这个改动在范围契约第 3 节里吗？不在的话走准入规则了吗？
- [ ] 有没有"顺手做了"计划外的东西？

**安全**
- [ ] 所有查询走 `withTenant()` 了吗？
- [ ] Server Action 校验了会话 + 角色 + 数据归属吗？
- [ ] 新建的表有 RLS 策略吗？有泄漏测试吗？
- [ ] 有没有把技术细节暴露给用户？

**质量**
- [ ] 业务规则是纯函数吗？能被单测覆盖吗？
- [ ] 文件超过行数上限了吗？
- [ ] 有 `any` / `as` / `@ts-ignore` 吗？
- [ ] 注释解释的是"为什么"还是"做了什么"？

**数据访问**
- [ ] 业务池查询由服务端角色范围约束，客户端参数不能扩大权限吗？
- [ ] 列表使用稳定游标，且没有深 OFFSET、无界 COUNT、全量历史 JOIN 或 N+1 吗？
- [ ] 新查询在代表性容量上检查过执行计划吗？

**UI**（前端改动）
- [ ] 同一条数据在页面上出现几次？（必须 1 次）
- [ ] 列表项有可点击的动作按钮吗？
- [ ] 四态都实现了吗？
- [ ] 390px 下能用吗？

**验证**
- [ ] typecheck / lint / test 都过了吗？
- [ ] 浏览器实际点过了吗？
- [ ] 迁移和代码在同一次提交吗？
