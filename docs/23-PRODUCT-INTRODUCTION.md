# Super CRM · 产品介绍

> 一页纸速览。详细设计见 [产品定位](./01-PRODUCT-OVERVIEW.md)、[功能规格](./03-FEATURE-LEAD.md)、[技术架构](./14-TECH-ARCHITECTURE.md)。

---

## 1. 定位

**为成交而生的开源 CRM。**

缩短销售周期，让有价值的线索不再被漏掉。

面向 B2B 销售团队，覆盖线索 → 客户 → 商机 → 成交完整闭环，AI 在每一步给出可执行建议。

**给谁用：** 一线销售（首要）、销售主管（次要）、系统管理员（辅助）。典型场景是 20–100 人公司、5–20 人销售团队，线索来自官网表单、API 投放、展会与转介绍。

---

## 2. 解决什么问题

**销售为什么不用 CRM：** 传统 CRM 的信息流是单向的——销售录入，管理者查看。录入成本由一线承担，收益归管理层。这个结构决定了数据质量难以维持：字段逐渐失真，主管不再看报表，最终回到 Excel 与微信群。

**三个具体表现：**

- 线索分散、跟进靠人记；有意的线索无人跟进，人员流动即带走客户关系
- 填单成本高（一条线索 5–6 个下拉、两分钟起），打开只见列表不知"今天先跟谁"
- 重复与撞单、公海无人打捞；赢单靠个人经验，方法无法复制

**我们的判断：** 销售只为两件事用工具——多签单，或省时间。系统按此顺序设计：先让销售得利，管理价值是副产品。

---

## 3. 两个结果，如何实现

**缩短销售周期**

- 线索打分排序，优先跟进高价值客户，减少无效触达
- 商机阶段停滞预警：超过 SLA 天数（探索 7 天 / 方案与谈判 14 天）触发任务与通知
- 跟进节奏由系统排期，不依赖个人记性
- 经营分析追踪平均成交周期与赢单率，改进效果可量化

**减少线索流失**

- 首响 SLA：线索分配后 24 小时内未跟进自动提醒
- 公海回收：长期无人跟进的线索按规则（7 / 30 / 60 天 + 3 天保护期）回收
- 冲突判定：重复与撞单在录入时拦截，不丢失既有跟进历史

## 4. 核心差异化

**从"记录"到"建议"。** 每条建议包含对象、标题、业务证据、建议动作与截止时间；建议失败不回滚业务事实。

**AI 走完整 Agent 循环，而非对话套壳。** 推理 → 调用真实业务工具 → 观察结果 → 再推理（上限 8 轮）。工具层直接复用业务 service，因此每句结论都能追溯到数据库记录。

**认知金字塔 L1–L4。** 赢单归因（为什么赢/输/停滞）→ 销冠解构（销冠客户长什么样）→ 企业画像（钱从哪来、谁在流失）→ 策略推导（获什么客、怎么转化）。L4 的合法性来自 L1–L3 的证据，认知先行、指挥在后。

**诚实边界。** 真实赢单样本 < 20 时所有结论强制标注`方向性假设（低置信度，样本 N=x）`；AI 总开关关闭时 `fail-closed` 零外发；无 Key / 超时 / 格式异常时降级内置规则。页面不展示模型思维过程，只展示可核验的业务证据。

## 5. 功能导览

| 环节 | 销售得到 | 主管 / 管理员得到 |
|---|---|---|
| **多渠道进线** | 手工 / CSV / 公开表单 / 外部 API 统一查重与评分 | 来源密钥管理、限流、撞单审计与幂等 |
| **线索池治理** | 5 档冲突判定（他人私海强阻断 / 自己重复直达 / 公海一键认领 / 撞客拦截 / 放弃重激活） | 公海自动回收、指派上限、容量看板 |
| **跟进与任务** | 极速录入 + 智能提炼、下一步自动排期 | 首响 24h SLA、超时与临近判定、今日工作台四档排序 |
| **智能评分** | 0–100 可解释分与理由，销售可反馈准确 / 不准确 | 规则权重可配、自动重算 |
| **客户与联系人** | 单位 / 个人双轨、决策链 6 角色标签、主联系人唯一 | 一客多线索协同、软删与审计 |
| **商机与报价** | 7 阶段推进（相邻校验、回退需原因）、赢 / 输单归档、报价行项目自动回写总额 | 阶段停滞识别、报价快照、预测三档 |
| **通知与工作台** | 站内收件箱、任务到期提醒 | 扫描去重 + 并发安全 |
| **AI 教练** | 推进质检（缺决策人 / 缺预算 / 缺时间线 / 无下一步 / 超期停滞）、一键采纳建任务 | 赢单复盘自动稿、打法发布门槛与版本化、推荐按阶段 / 行业 / 规模加权、反馈闭环 |
| **组织与权限** | 归属清晰的客户与商机 | 权限位体系、自定义角色、部门树、组织导入、离职交接、销售配额大盘 |

## 6. 架构要点

- **多租户硬隔离：** 共享库 + `FORCE ROW LEVEL SECURITY`，`withTenant` 事务内设置租户上下文。每张业务表配隔离测试。适合 SaaS 或多事业部部署。
- **插件化扩展：** 核心（`src/core`）禁止导入插件（`src/plugins`），插件仅经 `plugin-kit` 白名单与核心交互。停用任何插件不影响核心闭环，可按需上线模块。
- **行为级测试：** 550 条测试全部为行为断言（真数据库、真服务、真 HTTP handler），零 skip。覆盖租户隔离、状态机穷举、金额守恒与并发幂等。不使用"源码含某字符串"这类假测试。

**容量口径：** 目标基线为 100 万客户 / 500 万线索 / 5000 万跟进。当前证据为 smoke（1000 客户 / 5000 线索 / 2 万跟进）与单租户 1% 热缓存（1 万客户 / 5 万线索 / 50 万跟进）已通过。**未宣称百万级达标**，大规模数据前请自行压测（[容量基线](./19-CAPACITY-BASELINE.md)）。

## 7. 边界与免责

- **当前为演示-试用基线。** 聚焦"线索 → 客户 → 商机 → 建议 → 复盘"闭环。明确不做：营销自动化、提成计算、双向 CRM 同步、工作流引擎、自定义对象 / 字段。
- **AI 是副驾驶。** 建议依附 CRM 事实与已审核打法，不替销售做业务决定。样本不足时以人的经验权重为高。
- **安全与合规。** 参照三级等保思路设计（账号锁定、审计留痕、敏感字段脱敏、加密存储），具体以实际部署与配置为准（[部署运维手册](./22-DEPLOYMENT-OPERATIONS.md)）。演示数据为合成，生产环境需替换为客户自有数据并执行备份恢复演练。

## 8. 关于开源版

本仓库为 **主代码开源（AGPL-3.0）+ 业务插件闭源** 的发行版：

- **包含：** 完整核心 CRM、AI Agent 体系、插件框架（契约 / 装配点 / 挂载点 / 启停表）
- **不含：** 7 个业务插件实现（合同、订单、交付项目、BI 矩阵、获客表单、知识库、智能分发）及其数据表

插件缺席时系统完整可用，该降级行为有行为级测试锁定。二次开发可自行挂载插件，契约见 [插件契约](./13-PLUGIN-CONTRACT.md)。

**快速体验：**

```bash
pnpm docker:dev && pnpm db:seed:demo
```

访问 `http://localhost:3000/login`，账号 `admin@example.com` / `password123`（开发默认值）。
