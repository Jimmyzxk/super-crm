# 商脉 AI CRM · 产品介绍（一页纸）

> 版本 v1.3 · 2026-09-09 · 演示-试用阶段 · 措辞与数据均从 `docs/01 / 03-09 / 18 / 20 / 21 / 14 / 19` 与代码现况提炼

---

## 1. 给谁用、解决什么

**目标用户：** 20–100 人 B2B 企业的一线销售（首要）、销售主管（次要）、系统管理员（辅助）。线索来自官网表单、API 投放、展会与转介绍，团队常为 5–20 人（见 `docs/01 1.1 / 02`）。

**真实痛点（购买过 CRM 仍回到 Excel/微信的原因）：**

- 线索分散、跟进靠人记，主管只能开会问；上周“挺有意向”的线索本周无人跟进，换人即带走客户关系。
- 销售不愿填单：一条线索要点 5–6 个下拉、两分钟起；打开 CRM 只见列表报表，不知“今天先跟谁”。
- 重复与撞单、数据脏、公海无人打捞；赢单靠个人经验，方法无法复制。

**判断：** 销售只为两件事用工具——帮我多签单，或帮我省时间（`docs/01 1.3`）。系统按此顺序设计：先让销售得利，管理价值为副产品。

## 2. 核心差异化（克制陈述）

**不是再做一张表单，是把销冠打法沉淀为可执行建议。**

- **从“记录”到“建议”：** 围绕 `01` 三价值闭环——打开知道先跟谁（自动评分+今日队列）、30 秒记完（方式/结果/一句话，下一步自动建任务）、到点提醒（超时 5 分钟内通知）。每条建议含对象/标题/证据/动作/截止时间，失败不回滚业务事实。
- **认知金字塔 L1-L4（`docs/21` 第二层）：** L1 赢单归因（为什么赢/输/停滞）→ L2 销冠解构（销冠客户长什么样、路径差在哪）→ L3 企业画像（钱从哪来、谁在流失）→ L4 策略推导（获什么客、怎么转化、找谁增量变现）。L4 合法性来自 L1-L3 证据，**认知先行、指挥在后**。
- **诚实标注与引擎状态：** 真实赢单样本 `<20` 时所有结论强制标注 `方向性假设（低置信度，样本 N=x）`；AI 总开关 `is_ai_copilot_enabled=false` 时 `fail-closed` 零外发；无 `API Key`/超时/格式异常自动降级内置规则。页面**不展示**模型思维过程，仅展示可核验业务证据。

> 差异不在“模型更强”，在“马具”：工具层（`service → AgentTool`，代码实计 18 个）+ 循环层（ReAct 推理→调工具→观察→再推理，上限 8 轮）+ 护栏层（RLS 隔离/审计/Token 计量/确认闸门）。缺一不立项（`docs/21 三层缺一不立项`）。

## 3. 功能导览（按 `docs/01 5.1 / 03-09 / 18 / 20` 提炼）

| 环节 | 销售得到 | 主管/管理员得到 |
|---|---|---|
| **多渠道进线** | 手工/CSV/表单 `/f/[formId]`/外部 `POST /api/v1/leads` 统一查重与评分 | 来源密钥管理、限流 `10/min/IP`、撞单审计与幂等 `Idempotency-Key` |
| **线索池治理** | 5 档冲突判定（他人私海强阻断 / 自己重复直达 / 公海一键认领 / 撞客拦截 / 放弃重激活） | 公海自动回收（`7/30/60天` + 3天保护期 + 临期通知）、指派上限 50 条/批、容量看板 |
| **跟进与任务** | 30 秒极速录入 + 智能提炼（文本→结构化建议，人工确认）、下一步自动排期、日历同步 | 团队 SLA（首响 24h、超时/临近判定）、今日工作台四档排序（超时最前） |
| **智能评分** | 0-100 可解释分与理由（13 字段、8 类 operator）、销售反馈 `ACCURATE/INACCURATE` | 规则权重 -100~100、排序与截断、自动重算 |
| **客户与联系人** | 单位/个人双轨、决策链 6 角色标签、主联系人唯一、关联线索历程穿透 | 一客多线索/多商机协同、软删与审计 |
| **商机与报价** | 7 阶段推进（相邻校验、回退需原因）、赢/输单归档、`LineItems` 挂载自动回写总额 | 阶段停滞 `STAGE_PUSH`、报价快照、预测三档（Commit/Weighted/Best Case） |
| **通知与工作台** | 铃铛未读、站内收件箱、任务到期提醒 | 扫描去重 `(task_id,type)` + `SKIP LOCKED` |
| **AI 教练** | 推进质检（`MISSING_DECISION_MAKER / BUDGET / TIMELINE / NO_NEXT_STEP / OVERDUE / STALLED ...`）、下一步与截止时间、采纳一键建任务 | 赢单复盘（周期/停留/跟进/异议自动稿）、打法发布门槛 `≥3 已审核样本` + 版本化、推荐按阶段/行业/规模/地域加权 `Score = W_stage+W_industry+W_size+W_region+W_samples`、反馈 `有帮助/无帮助/不适用` 闭环 `ai_agent_learning_logs` |
| **扩展插件** | 表单获客、知识库（RAG 分块，`docs/20` 14 节）、智能分发（来源/行业/地区/分值全条件） | 合同-订单-交付-回款-发票-ASC606、BI 矩阵（速率 `V=N·S·W/T`、漏斗损耗、库龄光谱） |

导航五层：工作台/消息 → 线索/客户/商机/产品 → 经营分析/打法 → 获客表单 → 系统配置（`docs/20 7.4`）。

## 4. 架构亮点（与 `docs/14 / 11 / 16` 一致）

- **多租户 RLS 硬隔离：** 共享库、`FORCE ROW LEVEL SECURITY`、`withTenant` 事务内 `set_config('app.tenant_id',...,true)`；`tenants` 不启用 RLS 供登录与巡检枚举，`auth_lookup_user` 为专用 `NOLOGIN BYPASSRLS` 属主持有的 `SECURITY DEFINER`，其余 `salescrm` 应用角色永不 `BYPASSRLS`（`performance` 与 `product-catalog` 分区无关读模型未引入）。
- **行为级测试：** 82 文件 **641 用例全部通过、零 skip**；覆盖租户隔离（每表至少 1 条泄漏测试）、状态机穷举、计费守恒与并发幂等等价性，非“行覆盖率”导向（`docs/16` 哲学：每条必能说清防止什么真实故障）。
- **插件分层零反向耦合：** `core` 禁止 `import plugins`，`plugins` 仅经 `plugin-kit` 白名单 `ctx.core.createLead` 写核心；`eslint no-restricted-imports` + `scripts/check-layer-boundary.ts` + `plugin-boundary` 单元测试三重守卫，停用插件不影响核心闭环。

容量口径：`100万客户 / 500万线索 / 5000万跟进` 为目标基线，当前证据为 `smoke（5000线索）+ 单租户 1% 热缓存（1万客户/5万线索/50万跟进）` 已通过，**未宣称百万级达标**（`docs/19`）。

## 5. 免责与适用范围

- **演示-试用阶段：** 本版本为销售智能闭环的可用基线，聚焦“线索→客户→商机→建议→复盘”链路；营销自动化、复杂公海/抢单、提成计算、双向 CRM 同步、工作流引擎、自定义对象/字段、对象存储上传等**明确不做**（`docs/00 4`），按准入规则评估后置。
- **AI 为副驾驶：** 建议依附 CRM 事实与已审核打法，不替销售做业务决定；低样本期以人的经验权重为高。
- **安全与合规：** 口径对齐 `docs/20 18`（三级等保参考：MFA/口令/锁定/审计 180 天/加密脱敏/RPO≤1h RTO≤4h），具体以部署与配置为准；演示库数据为合成，生产需替换为客户自有数据并执行备份恢复演练（`docs/22 5.3`）。

> 联系试用：提供 `docker-compose.dev.yml` 热更环境与一键演示数据（`pnpm db:seed:acceptance`，管理员/主管/销售账号 + 客户/线索/商机/打法库全链路），5 分钟可复现本页所述闭环。
