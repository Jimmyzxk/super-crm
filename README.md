# Super CRM

**一个销售愿意天天用的开源 CRM —— 它不只记录发生了什么，而是告诉你下一步该做什么。**

给 20–100 人 B2B 销售团队，用 AI 把销冠的打法变成每个人都能执行的建议。

## 为什么还需要一个 CRM

如果你已经在用 Salesforce、HubSpot、纷享销客或钉钉 CRM，你大概见过这套循环：

> 系统上线三个月 → 销售开始敷衍填单 → 半年后字段全是"已联系"、金额随便填 → 主管不再看报表，回到微信群和 Excel → CRM 沦为"应付上级的打卡机"。

**这不是销售懒，是设计问题。** 传统 CRM 的信息流向是单向的：销售录入 → 管理者查看。录入的成本由销售的每一分钟承担，收益却归管理者。当一件事对做事的人只有成本、没有回报，它必然被敷衍——这是组织行为，不是道德问题。

Super CRM 的全部设计押在一个相反的假设上：**先让销售自己尝到甜头，管理价值是这件事的副产品。**

| 传统 CRM 让销售做的事 | Super CRM 让销售得到的东西 |
|---|---|
| 打开系统看到一张列表，自己判断先跟谁 | 打开就看到**今天该联系谁**，按优先级排好，附评分理由 |
| 填 6 个下拉 + 写一段周报式的跟进记录 | 只填**方式 / 结果 / 一句话**（约 30 秒），系统自动提炼结构化信息 |
| 靠自己记性记住下次什么时候跟进 | 系统**自动建下一步任务并排期**，到点提醒 |
| 线索跟丢了没人知道，月底才发现 | 停滞线索**自动预警**，超时任务自动标红 |
| 赢单经验留在个人脑子里，人走经验走 | 真实赢单被**提炼成可复用的打法**，沉淀在系统里 |

**所以，它到底给你什么？**

- **对销售**：每天省下 10–20 分钟找线索、想下一步、补记录的时间；不用记，系统替你记；客户跟丢了会被提醒而不是被追责。
- **对主管**：不用在例会上靠追问了解进度——团队的真实推进状态在系统里；哪个环节在漏、谁在停滞、哪种客户赢面高，都有数据支撑而不是凭感觉。
- **对老板**：销冠的经验不再随人流动而清零；获客渠道哪个值钱、商机卡在哪、钱从哪来，从"听汇报"变成"看事实"。

**它和"AI 套壳 CRM"的区别**

市面上不少产品在传统 CRM 上挂一个对话框，聊天记录和业务数据是两张皮。问它"这个客户该不该跟"，得到的通常是"建议您保持沟通、关注客户需求"这类正确的废话。

Super CRM 的 AI 走的是完整 Agent 循环——**推理 → 调用真实业务工具 → 观察结果 → 再推理**，工具层直接复用业务 service。同一个问题，它给出的回答长这样：

> **商机「某智能装备 · 标准版订阅」推进停滞 23 天**
> - 缺口：**决策人未接触**（当前主联系人无采购 / 预算相关角色）
> - 证据：距上次跟进 23 天；阶段停留在「方案沟通」；报价行项目尚未配置
> - 建议动作：3 日内约见技术负责人，议题围绕方案落地路径
> - 参照打法：**《高预算客户价值升维与快速锁单》**（按当前阶段 + 客户行业 / 规模匹配，关联 3 个真实赢单样本）

差别在于：**每句话都能追溯到数据库里的具体记录**，不是模型编的。而且它知道自己什么时候不该说话——样本不足时明确标注低置信度，模型不可用时降级到内置规则，而不是编一个看起来合理的答案。

我们对 AI 的能力边界做了几条硬约束：

- 真实赢单样本不足 20 条时，所有结论强制标注`方向性假设（低置信度，样本 N=x）`，不假装确定。
- 页面**不展示**模型的思维过程，只展示可核验的业务证据。
- AI 总开关关闭时 `fail-closed`：零外发请求，而不是静默降级成另一套说辞。
- 无 API Key / 超时 / 返回格式异常时降级到内置规则，不让用户卡住。

## 功能一览

### 销售日常：从"不得不填"到"用得上"

| 你遇到的问题 | Super CRM 的做法 |
|---|---|
| **线索进来靠人分，跟丢了才发现** | 多渠道进线（手工 / CSV / 公开表单 / 外部 API）统一查重与评分；5 档冲突判定（他人私海强阻断 / 自己重复直达 / 公海一键认领 / 撞客拦截 / 放弃重激活） |
| **线索烂在个人手里，别人碰不得** | 无人跟进的线索按规则自动回收（`7 / 30 / 60 天` + 3 天保护期 + 临期预警），回到公海供团队认领 |
| **不知道该先跟谁，全凭感觉** | 13 字段加权评分（权重可配、自动重算、理由可查），到期 / 停滞 / 沉默自动预警，销售还能反馈评分准不准 |
| **填单太麻烦，销售不愿意记** | 极速录入（方式 / 结果 / 一句话）+ 智能提炼，系统自动生成下一步任务并排期，超时判定与今日工作台四档排序（超时最前） |
| **客户信息散落，换人就断档** | 单位 / 个人双轨、决策链 6 角色标签、主联系人唯一、线索到客户的完整历程穿透 |
| **商机卡在哪说不清，月底才发现** | 7 阶段推进（相邻校验、回退需原因）、报价行项目挂载自动回写总额、阶段停滞自动识别 |
| **该跟进的时候没人提醒** | 站内收件箱 + 任务到期提醒，扫描去重 + 并发安全（`SKIP LOCKED`），超时 5 分钟内触达 |

### AI 能力（真正的 Agent，不是套壳）

六个常驻 Agent 走完整的 **ReAct 循环**（推理 → 调用工具 → 观察 → 再推理，上限 8 轮），工具层直接复用业务 service，每次执行留痕可追溯：

| Agent | 做什么 | 你能拿它干什么 |
|---|---|---|
| **晨会副驾驶** | 每天给对方销售生成"今天三件事"，每条附业务证据与一键建任务 | 早上打开就知道今天该做什么，不用自己想 |
| **推进质检** | 发现商机推进缺口：缺决策人 / 缺预算 / 缺时间线 / 无下一步 / 超期停滞 | 主管不用逐个问，问题自己浮出来 |
| **赢单 · 输单归因** | 从真实赢单样本中提炼为什么赢、为什么输 | 复盘不再靠印象，有样本可依 |
| **销冠解构** | 分析销冠客户画像与推进路径差异 | 把"他为什么行"变成"我们都能照着做" |
| **企业画像** | 钱从哪来、谁在流失、增量在哪 | 经营决策有事实支撑，而非听汇报 |
| **管线健康巡检** | 主动发现风险商机与异常 | 风险在变成损失之前被看见 |

**关于诚实的几个具体做法**（我们认为这比"模型更强"更重要）：

- 真实赢单样本不足 20 时，所有结论强制标注`方向性假设（低置信度，样本 N=x）`，不假装确定。
- 页面**不展示**模型的思维过程，只展示可核验的业务证据。
- AI 总开关关闭时 `fail-closed`：零外发请求，而不是静默降级成另一套说辞。
- 无 API Key / 超时 / 返回格式异常时降级到内置规则，不让用户卡住。

### 架构与工程

- **多租户硬隔离**：共享库 + PostgreSQL `FORCE ROW LEVEL SECURITY`，`withTenant` 事务内设置租户上下文；每张业务表都有对应的隔离测试。适合做 SaaS 或多事业部部署。
- **插件化扩展**：核心保持对插件零依赖，插件通过白名单接口与核心交互。停用任何插件都不影响核心闭环——这意味着你可以只上核心功能，按需追加模块。
- **行为级测试**：550 条测试全部是行为断言（真数据库、真服务、真 HTTP handler），不使用"源码里包含某字符串"这类假测试。零 skip。改代码时你能相信测试真的测到了东西。

## 快速开始

**前置条件**：Node.js 22、pnpm 9.15.5、Docker。

```bash
git clone https://github.com/Jimmyzxk/super-crm.git
cd super-crm

cp .env.example .env          # 开发默认值可直接用；生产请按注释用 openssl 生成强随机密钥
pnpm install
pnpm docker:dev               # 启动 PostgreSQL + 应用容器（代码改动即时生效）

# 数据库迁移：容器启动时已自动执行；宿主机直连时手动跑
pnpm db:migrate

# 演示数据（幂等，可重复执行）
pnpm db:seed:demo
```

打开 http://localhost:3000/login，用开发默认账号登录：

```
邮箱：admin@example.com
密码：password123
```

> 生产部署（含 HTTPS 证书终止、环境变量清单、备份与恢复演练、故障排查）见 **[部署运维手册](./docs/22-DEPLOYMENT-OPERATIONS.md)**。

## 关于发行形态

本仓库是 **「主代码开源 + 业务插件闭源」** 的发行版：

- **包含**：完整核心 CRM、AI Agent 体系、插件框架（契约定义 / 装配点 / UI 挂载点 / 启停与限流表）。
- **不包含**：7 个业务插件的实现（合同、订单、交付项目、BI 矩阵、获客表单、知识库、智能分发）及其数据表——它们是闭源组件。

**插件缺席时系统完整可用**：导航不会出现幽灵入口，详情页挂载点与设置分区渲染为空，AI 报告中的插件相关段落为空——核心链路不受影响。这一降级行为有行为级测试锁定。

**二次开发挂载自己的插件**：在 `src/plugins/<your-plugin>/` 实现 `definePlugin({...})`，在 `src/plugin-kit/registry.ts` 的 `compiledPlugins` 里 import 并 push 即可，上游调用点无需任何改动。契约见 [插件契约](./docs/13-PLUGIN-CONTRACT.md)。
